# pkg-manager · 内置 Git 包管理器

> 状态：设计定稿，待实现。定稿时间：2026-10-20。
> 上级索引：[../PLAN.md](../PLAN.md)。本文档是包管理子系统的权威规格。

## 1. 定位与决策

内置到 `tphp` CLI 的 Git 包管理。**不调用任何托管平台 API**（GitHub/Gitee/GitCode/自建 Gitea 同构，纯 `git` 子进程）；**不做远程注册表**，发布即「git push + tag」。

| 决策点 | 结论 |
|---|---|
| 清单/锁文件 | `mod.json` / `mod.lock` |
| 包 ID | `foo/bar`（斜杠分层，Composer/npm 同款） |
| vendor 布局 | `vendor/foo/bar/` 嵌套；全项目共享拍平，禁止嵌套 vendor |
| 自动加载 | PSR-4 + `files`；`install` 生成 `vendor/autoload.php` |
| 版本解析 | tag + 本地 semver 排序；不调平台 Release API |
| 私有仓库 | 不自建 auth；https 走 credential helper，ssh 走 key |
| 远程注册表 | 不做；`tphp upload` 占位打印发布指引 |
| `main` 字段 | 不设（autoload 覆盖库加载；应用入口命令行指定） |
| 单一 `namespace` 字段 | 不设（包可多命名空间，用 `autoload.psr-4` 映射表） |

## 2. 文件格式

### 2.1 `mod.json`（清单）

```jsonc
{
  "name": "foo/bar",             // 包 ID：vendor/<name>/ 路径；小写 [a-z0-9_-]/
  "version": "1.2.0",            // 语义化版本
  "type": "lib",                 // "app" | "lib"
  "author": "Foo Team <foo@example.com>",
  "description": "字符串工具",
  "license": "MIT",
  "autoload": {                  // 可选；app 与 lib 均可有（应用自身类同样走 use + 自动加载）
    "psr-4": {
      "Foo\\Bar\\": "src/"      // 可多条：命名空间前缀 → 目录
    },
    "files": ["src/helpers.php"] // 可选：autoload 时无条件加载（函数/常量）
  },
  "pack": {                      // 可选；控制 tphp build 打包内容
    "include": ["assets/", "config/prod.php"],  // 额外打包（相对项目根；文件或目录）
    "exclude": ["*.log", "docs/", "notes.txt"]  // 额外排除（glob / 目录前缀）
  },
  "deps": {                      // 可选
    "acme/utils": {
      "git": "https://gitee.com/acme/utils.git",
      "ref": "^1.0"             // 见 §3 版本规格
    }
  }
}
```

字段一览：

| 字段 | app | lib | 说明 |
|---|---|---|---|
| `name` | ✅ | ✅ | 包 ID，映射 `vendor/<name>/` |
| `version` | ✅ | ✅ | 语义化版本 |
| `type` | ✅ | ✅ | `app` \| `lib` |
| `author` | 可选 | 可选 | |
| `description` | 可选 | 可选 | |
| `license` | 建议 | 建议 | `tphp build` 再分发时追溯 |
| `autoload` | 可选 | 可选 | `psr-4` + `files`；应用自身类同样可用 |
| `pack` | 可选 | 可选 | `include`/`exclude`，控制 `tphp build` 打包集 |
| `deps` | 可选 | 可选 | `"foo/bar": { git, ref }` |

**无 `main`**：autoload 覆盖库的类加载；应用入口由 CLI 指定（`tphp run src/index.php`）。
**无单一 `namespace`**：包可含多个命名空间，由 `autoload.psr-4` 映射表声明。

### 2.2 `mod.lock`（锁定，生成物，建议提交）

```jsonc
{
  "foo/bar": {
    "git": "https://github.com/foo/bar.git",
    "ref": "v1.2.0",            // 用户声明的原始规格
    "commit": "a1b2c3d4e5f6…",  // 解析后的精确 SHA
    "resolved": "2026-10-20T16:30:00Z"
  }
}
```

### 2.3 目录布局

```
my-project/
├── mod.json
├── mod.lock
├── src/index.php
└── vendor/                      # 全项目共享，拍平
    ├── foo/
    │   └── bar/                 # vendor/<name>/
    │       ├── mod.json
    │       └── src/…
    ├── acme/
    │   ├── utils/               # 同 vendor 多包并列
    │   └── http/
    └── autoload.php             # install/add 时生成
```

规则：
- 包 ID `A/B` → 磁盘 `vendor/A/B/`
- 传递依赖拍平到顶层；**禁止**包内嵌套 `vendor/`
- 包名以包内 `mod.json` 的 `name` 为准（URL 末段仅 fallback）

### 2.4 `vendor/autoload.php`（生成物）

生成逻辑：合并**根项目自身** `mod.json` 的 autoload 段 + 所有 `vendor/*/mod.json` 的 autoload 段，拼接为一个文件。示例（根项目也声明了 autoload）：

```php
<?php
/* AUTO-GENERATED by tphp — do not edit.
 * Recomputed on every install/add/remove. */

// 1) files：无条件加载（根项目 + 所有依赖）
require_once __DIR__ . "/../src/helpers.php";           // 根项目
require_once __DIR__ . "/foo/bar/src/helpers.php";      // 依赖

// 2) PSR-4 映射表：namespace 前缀 → 目录列表
$psr4 = [
    "App\\" => [__DIR__ . "/../src"],                    // 根项目自身
    "Foo\\Bar\\" => [__DIR__ . "/foo/bar/src"],          // 依赖
    "Acme\\Http\\" => [__DIR__ . "/acme/http/src"],
];

// 3) 注册 autoloader（走 TinyPHP 已有 spl_autoload_register）
spl_autoload_register(function (string $class) use ($psr4) {
    $norm = str_replace("\\", "/", $class) . ".php";
    foreach ($psr4 as $prefix => $dirs) {
        if (strncmp($class, $prefix, strlen($prefix)) !== 0) continue;
        $rel = substr($norm, strlen(str_replace("\\", "/", $prefix)));
        foreach ($dirs as $dir) {
            $f = $dir . "/" . $rel;
            if (is_file($f)) { require $f; return; }
        }
    }
});
```

用户入口：

```php
<?php
require "vendor/autoload.php";
use Foo\Bar\Str;        // 首次使用时自动加载
use Acme\Http\Client;
```

## 3. `ref` 版本规格

| 写法 | 解析方式 | 说明 |
|---|---|---|
| `dev` | 默认分支 tip | `git clone` / `checkout` 默认分支 |
| 分支名（`main`/`develop`） | 该分支 tip | |
| `v1.2.0` / `1.2.0` | 精确 tag | `ls-remote --tags` 匹配，自动试 `v` 前缀 |
| `^1.0` / `~1.2` | 最高兼容 semver tag | 本地对 tag 列表 semver 排序 |
| 省略 / `latest` | 最高 semver tag | 无 tag 则回退默认分支 + 警告 |
| 40 位 SHA | 该 commit | `git fetch <sha> && checkout` |

「最新发布版」= tag + 本地 semver 排序，**不调 GitHub/Gitee Release API**——tag 是发布事实，Release 只是展示层；且避免为每个平台写一套认证与响应解析。无 tag 仓库回退默认分支并对齐 Composer `dev-main` 行为。

## 4. 命令规格

### 4.1 `tphp new <name> [--lib]`

```
tphp new my-app           # 应用骨架
tphp new --lib foo/bar    # 库包骨架
```

生成：

```
# 应用
mod.json          # name, version 0.1.0, type app, license MIT
main.php          # 入口：require "vendor/autoload.php"; + 起步代码
README.md
.gitignore        # vendor/

# 库包
src/              # 命名空间根目录（示例类）
tests/            # test-smoke.php
README.md
.gitignore        # vendor/
```

`main.php` 示例：

```php
<?php
require "vendor/autoload.php";

echo "Hello, world\n";
```

`name` 校验：应用允许单段名（无斜杠）作为项目名；库包必须 `^[a-z0-9][a-z0-9_-]*/[a-z0-9][a-z0-9_-]*$`（小写，斜杠分层）。

### 4.2 `tphp add <git-url>[:ref]`

1. 解析 URL + ref（缺省 `latest`）
2. 查 `mod.json` `deps`：同名已存在则更新 ref；否则新增
3. `git ls-remote` 解析 commit SHA
4. `git clone --depth 1` 到临时目录 → 检出 → 拷贝到 `vendor/<name>/`（排除 `.git`）
5. 读包内 `mod.json` 取真实 `name`（与 URL 推导不一致时以包内为准，调整路径）
6. 递归处理包的 `deps`（传递依赖拍平；同名冲突：semver 兼容取最高，不兼容 Fatal 并打印依赖链）
7. 写 `mod.json` + `mod.lock`
8. 重新生成 `vendor/autoload.php`

`add` 对已存在依赖 = 更新该包 ref 并重装。

### 4.3 `tphp remove <name>`

1. `mod.json` `deps` 删除该项
2. 递归清理：仅被该包独占的传递依赖删除；仍被其他依赖引用的保留
3. 删 `vendor/<name>/`
4. 写 `mod.lock`，重新生成 autoload.php

### 4.4 `tphp install`

按 `mod.lock` 逐包恢复（vendor 已存在则跳过，离线友好）；无 lock 则从 `mod.json` deps 全量递归解析。完成后重写 lock + autoload。CI/新机器主入口。

### 4.5 `tphp upload`（占位）

不实现远程。输出：

```
发布即推送：
  1. 确保 mod.json 的 version 已更新
  2. git tag v<version> && git push --tags
  3. （可选）未来注册表见 PLAN/pkg-manager.md §7
```

## 5. 架构拆分

新增 C 模块 + CLI 接入；**不动 VM**。

```
src/
├── pkg.c / pkg.h      # 包管理核心
│   ├── mod.json 解析/序列化（轻量专用，不必通用 JSON 引擎）
│   ├── git 子进程封装（ls-remote / clone --depth 1 / checkout）
│   ├── vendor 布局管理
│   ├── mod.lock 读写
│   ├── autoload.php 生成
│   └── 依赖图：递归解析、拍平、冲突检测
│
├── main.c             # CLI 路由：new/add/remove/install/upload
└── (现有) pack.c      # build 时 --with vendor/ 无需改
```

### 5.1 关键实现点

| 点 | 方案 |
|---|---|
| JSON | 现有 `json.c` 编解码到 TVal。新增轻量 `mod_json` 读写（name/version/type/autoload/deps 五段） |
| git 调用 | `system()` / `_popen`；Windows/Unix 分支处理引号与路径；失败透传 git stderr |
| semver | 简单比较器：`major.minor.patch`；支持 `^` `~` `latest` |
| 传递依赖 | DFS + visited 集；冲突：宽版本约束满足取最高，否则 Fatal 列两条链 |
| autoload 生成 | 遍历 `vendor/*/mod.json` autoload 段，拼接 PHP |
| 路径分隔符 | 统一 `/`；Windows 下 git 输出转换 |

### 5.2 与现有系统衔接

| 系统 | 影响 |
|---|---|
| `require` | **零改动**——`vendor/foo/bar/src/x.php` 字面量路径，现有编译期内联 + 运行期 OP_REQUIRE 均可解析 |
| `tphp build` | 见 §5.3 打包衔接 |
| bundle (phpc) | 不冲突——phpc 是 exe 内置 stdlib，vendor 是项目级依赖 |
| autoload | 生成的 `spl_autoload_register` 走 TinyPHP 已有 autoload 机制 |

### 5.3 打包衔接（`tphp build`）

#### 默认打包集

| 内容 | 来源 |
|---|---|
| 入口脚本 | 命令行指定（如 `main.php`） |
| `vendor/` | 有 `mod.json` 且未显式 `--with` 时自动加入 |
| 用户 `--with` | 显式传入的路径 |

#### `mod.json` 的 `pack` 字段

用户在清单里声明打包偏好，`tphp build` 读取并应用：

```jsonc
"pack": {
  "include": ["assets/", "config/prod.php"],
  "exclude": ["*.log", "docs/", "notes.txt", "vendor/foo/bar/tests"]
}
```

| 键 | 类型 | 语义 |
|---|---|---|
| `include` | string[] | **额外**打包路径（相对项目根；文件或目录）。在默认集与 `--with` 之外追加 |
| `exclude` | string[] | **排除**规则，作用于最终打包集。支持：精确路径、目录前缀（尾 `/`）、glob（`*` `?`，匹配 basename 或相对路径尾段） |

匹配规则：
- 目录规则 `"docs/"` → 整目录跳过（含子文件）
- glob `"*.log"` → 任意层级同名后缀文件跳过
- 精确路径 `"vendor/foo/bar/tests"` → 仅跳该目录
- `exclude` 优先级高于 `include` 与默认集（写了就以排除为准）

示例：

```jsonc
// 应用：打包 vendor + assets，但排除内部文档和日志
{
  "name": "my-app",
  "type": "app",
  "pack": {
    "include": ["assets/"],
    "exclude": ["*.log", "docs/", "assets/internal/"]
  },
  "deps": { "foo/bar": { "git": "…", "ref": "v1.0" } }
}
```

```
tphp build main.php -o demo
# 实际打入：main.php + vendor/**（默认排除 tests/.git）+ assets/**（排除 internal/ 与 *.log）
```

#### 收集排除规则（vendor 自动打包时生效）

pack 目录遍历时跳过以下内容，避免垃圾进单文件：

| 跳过 | 原因 |
|---|---|
| `.git/`、`.gitignore`、`.gitattributes` | VCS 元数据 |
| `.DS_Store`、`Thumbs.db` | 系统垃圾 |
| `*.md` | README 等文档（可选，保持包体精简） |
| 依赖包内的 `tests/`、`test/` 目录 | **测试代码不进生产**；包自身的 `tests/` 同理 |

保留：`mod.json`（运行期可读包元数据）、`src/`、`autoload.php`、其余运行时需要的资源。

> 用户显式 `--with` 某目录时：不跳过 tests/（尊重显式指定），仅跳过 `.git` 等 VCS/系统垃圾。

#### `.php` 文件进 zip（已实现）

`collect_dir` **不再跳过 `.php`**——vendor 里的 PHP 源码是 autoload 运行期 `OP_REQUIRE` 的目标，必须进 zip。VCS/系统垃圾（`.git`/`.DS_Store` 等）仍恒跳过；自动 `--with vendor/` 时额外跳过 `tests/`、`test/`、`*.md`（`tphp_pack_set_vendor_strict`）。

#### 端到端链路（打包应用）

```
build 时：
  main.php 字面量 require "vendor/autoload.php" → 编译期内联（磁盘读）
  vendor/** → pack zip（source_root 相对路径作 key）

运行时：
  启动 → pack zip 常驻 → run_source(main) → 编译
  autoload.php 内 require_once __DIR__/... → 字面量折叠后 OP_REQUIRE
    → 磁盘 miss → source_root 剥离 → pack zip 命中
  use Foo\Bar\Str → spl_autoload → require $f（动态路径）
    → OP_REQUIRE → pack zip 命中
```

## 7. 边界与已知决策

| 项 | 决策 |
|---|---|
| 远程注册表 | 不做；`upload` 占位。未来若做：`upload` 只传 manifest + tarball；`add <pkg>` 无 URL 时才走注册表，lock 结构不变 |
| 私有仓库 | 不自建 auth；https 走 credential helper，ssh 走 key；add 失败透传 git 错误 |
| 包名冲突 | 传递依赖同名：semver 兼容取最高，不兼容 Fatal 报依赖链 |
| vendor 与 git | `tphp new` 默认写 `vendor/` 进 `.gitignore`；`mod.lock` 建议提交（可复现） |
| PHP 版本约束 | 暂不支持 `require.php` 字段（TinyPHP 自身版本即约束） |
| `autoload.classmap` | 暂不做（PSR-4 + files 覆盖主流）；后置 |
| Windows | git 可执行检测 + 路径分隔符归一 |
| 嵌套 vendor | 禁止（拍平共享，Composer 同款） |

## 9. 示例：端到端

```bash
# 创建应用
tphp new demo-app
cd demo-app

# 添加依赖（GitHub tag）
tphp add https://github.com/foo/bar.git:v1.2.0

# 添加依赖（Gitee dev 分支）
tphp add https://gitee.com/acme/utils.git:dev

# 业务代码写在 main.php（或自建 src/ 后改入口路径）
# main.php:
#   require "vendor/autoload.php";
#   use Foo\Bar\Str;
#   echo Str::upper("hi");

tphp run main.php

# 打进单文件（vendor 进 pack）
tphp build main.php --with vendor/ -o demo
```

```bash
# CI 恢复
tphp install
tphp run main.php
```
