# pkg-manager · 内置包管理器（无外部工具）

> 状态：**四阶段已实现**（A 2026-10-20 / B·C·D 2026-10-21）。定稿 2026-10-20；2026-10-21 演进为**无 git 版**（用户拍板：不要求用户机器安装 git）。
> 上级索引：[../PLAN.md](../PLAN.md)。本文档是包管理子系统的权威规格。用户文档见 [../doc/package-manager.md](../doc/package-manager.md)。

## 1. 定位与决策

内置到 `tphp` CLI 的包管理。**不依赖 git 或任何外部可执行程序**：包源为 HTTP(S) zip 直链、GitHub 仓库页 URL（zipball 下载，无 ref 时经 GitHub 匿名 API 解析最新发布）、本地路径（目录或 zip）。**不做远程注册表**，发布即「git tag + 可下载 zip」（发布者侧用 git 不影响消费者侧）。

| 决策点 | 结论 |
|---|---|
| 清单/锁文件 | `mod.json` / `mod.lock` |
| 包 ID | `foo/bar`（斜杠分层，Composer/npm 同款） |
| vendor 布局 | `vendor/foo/bar/` 嵌套；全项目共享拍平，禁止嵌套 vendor |
| 自动加载 | PSR-4 + `files`；`install` 生成 `vendor/autoload.php` |
| 包源 | zip 直链 / GitHub 仓库 URL（zipball）/ 本地路径或 zip；纯 C 下载+miniz 解压 |
| 版本解析 | GitHub 裸仓库 URL 无 ref → 匿名 API 解析最新发布并**固化进 mod.json**；zip URL 以 URL 为锚点（详见 §3、§7） |
| 私有仓库 | 不自建 auth；HTTPS 信任链 = 内嵌 Mozilla ∪ 系统 Root 存储 |
| 远程注册表 | 不做；`tphp upload` 占位打印发布指引 |
| `main` 字段 | 不设（autoload 覆盖库加载；应用入口命令行指定） |
| 单一 `namespace` 字段 | 不设（包可多命名空间，用 `autoload.psr-4` 映射表） |

## 2. 文件格式

### 2.1 `mod.json`（清单）

```jsonc
{
  "name": "foo/bar",             // 包 ID：vendor/<name>/ 路径；小写 [a-z0-9_-]/
  "version": "1.2.0",            // 语义化版本
  "type": "lib",                 // "app" | "lib"
  "author": "Foo Team <foo@example.com>",
  "description": "字符串工具",
  "license": "MIT",
  "autoload": {                  // 可选；app 与 lib 均可有（应用自身类同样走 use + 自动加载）
    "psr-4": {
      "Foo\\Bar\\": "src/"      // 可多条：命名空间前缀 → 目录
    },
    "files": ["src/helpers.php"] // 可选：autoload 时无条件加载（函数/常量）
  },
  "pack": {                      // 可选；控制 tphp build 打包内容
    "include": ["assets/", "config/prod.php"],  // 额外打包（相对项目根；文件或目录）
    "exclude": ["*.log", "docs/", "notes.txt"]  // 额外排除（glob / 目录前缀）
  },
  "deps": {                      // 可选
    "acme/utils": {
      "url": "https://github.com/acme/utils",  // GitHub 仓库 URL / zip 直链 / 本地路径
      "ref": "v1.2.0"             // 解析或声明的版本；见 §3
    }
  }
}
```

字段一览：

| 字段 | app | lib | 说明 |
|---|---|---|---|
| `name` | ✅ | ✅ | 包 ID，映射 `vendor/<name>/` |
| `version` | ✅ | ✅ | 语义化版本 |
| `type` | ✅ | ✅ | `app` \| `lib` |
| `author` | 可选 | 可选 | |
| `description` | 可选 | 可选 | |
| `license` | 建议 | 建议 | `tphp build` 再分发时追溯 |
| `autoload` | 可选 | 可选 | `psr-4` + `files`；应用自身类同样可用 |
| `pack` | 可选 | 可选 | `include`/`exclude`，控制 `tphp build` 打包集 |
| `deps` | 可选 | 可选 | `"foo/bar": { url, ref }`（读取兼容旧 `git` 键） |

**无 `main`**：autoload 覆盖库的类加载；应用入口由 CLI 指定（`tphp run src/index.php`）。
**无单一 `namespace`**：包可含多个命名空间，由 `autoload.psr-4` 映射表声明。

### 2.2 `mod.lock`（锁定，生成物，建议提交）

```jsonc
{
  "foo/bar": {
    "url": "https://github.com/foo/bar",  // 来源（GitHub 裸 URL 已剥 :ref 后缀）
    "ref": "v1.2.0",            // 解析/声明的版本（GitHub 裸 URL 的解析结果已固化）
    "resolved": "2026-10-20T16:30:00Z",  // 解析时间
    "integrity": {              // 落盘快照（阶段 E，待实现）：安装完成时
      "mod.json": "da39a3ee…",  //   vendor/<name>/ 全文件 sha1（相对路径，/ 分隔）
      "src/Str.php": "a94a8fe5…",
      "bin/foo.dll": "2fd4e1c6…"
    }
  }
}
```

无 `commit` 字段（无 git，SHA 不可得）；可复现性由「固化 ref + URL」保证。

**`integrity`（设计，阶段 E 待实现）**——防篡改快照，回答"我装的是不是我审过的那个"：

- **全文件**逐条 sha1（含 `.php`——它就是代码执行面，DLL 天然包含）；排除 `vendor/autoload.php` 等项目级生成物
- 逐文件明细而非整树单哈希：精确报错（"哪个文件被改"），树哈希留作日后大包优化
- 算法 **SHA-1**，复用 `pack.c` 实现（与 build 的 DLL manifest 校验同构；防篡改非防伪造，足够）
- 写入单点：`lock_save`（add/remove/install 尾部统一调用时顺手扫描生成）
- 校验点只有两个：**install 的 skip 判断**与 **build 打包 vendor 时**；运行时（`tphp run`）不校验
- 不匹配 = fail-closed 报错（列出文件）+ 显式 `tphp install --force` 才重装，不静默冲掉用户本地改动
- 新增文件也算不匹配（挡"侧载 DLL 进 vendor"）；旧 lock 无 `integrity` 段 = 不校验，下次 install 成功后自动补写（向后兼容）
- 本机制不引入密钥/标识/配置面——与 ffi-security.md 的结论一致（不做 FFI 标识、不做运行时总闸）

### 2.3 目录布局

```
my-project/
├── mod.json
├── mod.lock
├── src/index.php
└── vendor/                      # 全项目共享，拍平
    ├── foo/
    │   └── bar/                 # vendor/<name>/
    │       ├── mod.json
    │       └── src/…
    ├── acme/
    │   ├── utils/               # 同 vendor 多包并列
    │   └── http/
    └── autoload.php             # install/add 时生成
```

规则：
- 包 ID `A/B` → 磁盘 `vendor/A/B/`
- 传递依赖拍平到顶层；**禁止**包内嵌套 `vendor/`
- 包名以包内 `mod.json` 的 `name` 为准（URL 末段仅 fallback）

### 2.4 `vendor/autoload.php`（生成物）

生成逻辑：合并**根项目自身** `mod.json` 的 autoload 段 + 所有 `vendor/*/mod.json` 的 autoload 段，拼接为一个文件。示例（根项目也声明了 autoload）：

```php
<?php
/* AUTO-GENERATED by tphp — do not edit.
 * Recomputed on every install/add/remove. */

// 1) files：无条件加载（根项目 + 所有依赖）
require_once __DIR__ . "/../src/helpers.php";           // 根项目
require_once __DIR__ . "/foo/bar/src/helpers.php";      // 依赖

// 2) PSR-4 映射表：namespace 前缀 → 目录列表
$psr4 = [
    "App\\" => [__DIR__ . "/../src"],                    // 根项目自身
    "Foo\\Bar\\" => [__DIR__ . "/foo/bar/src"],          // 依赖
    "Acme\\Http\\" => [__DIR__ . "/acme/http/src"],
];

// 3) 注册 autoloader（走 TinyPHP 已有 spl_autoload_register）
//    前缀匹配用 substr+strlen（stdlib 无 strncmp）；长前缀在生成时已排前
spl_autoload_register(function (string $class) use ($psr4) {
    $norm = str_replace("\\", "/", $class) . ".php";
    foreach ($psr4 as $prefix => $dirs) {
        if (substr($class, 0, strlen($prefix)) !== $prefix) continue;
        $rel = substr($norm, strlen(str_replace("\\", "/", $prefix)));
        foreach ($dirs as $dir) {
            $f = $dir . "/" . $rel;
            if (file_exists($f)) { require $f; return; }
        }
    }
});
```

用户入口：

```php
<?php
require "vendor/autoload.php";
use Foo\Bar\Str;        // 首次使用时自动加载
use Acme\Http\Client;
```

## 3. `ref` 版本规格

包源三类，ref 语义各异（2026-10-21 无 git 版重写；原 git 时代「dev/分支/SHA/`^~` 约束」表已废弃）：

### GitHub 仓库页 URL

| 写法 | 解析方式 |
|---|---|
| 裸仓库 URL（无 ref） | 匿名 API 查最新发布：`releases/latest` → 失败回退 `tags` 列表本地 semver 排序 → 再失败回退默认分支 + stderr warning；**解析出的 ref 固化进 mod.json**（可复现） |
| `url:ref` 后缀 / CLI `ref` 参数 | 直接下 `zipball/<ref>`（tag/分支皆可；CLI 参数优先；含 `/` 的 ref 只能用 CLI 参数形式；`:ref` 只在 path 内最后一个 `/` 之后切，ref 限 `[A-Za-z0-9._-]`） |

支持 `owner/repo`、可选 `.git` 尾缀、`/tree/<分支>` 路径（优先级低于 `:ref`）。API 匿名限流 60 次/小时/IP（文档已注明）。

### HTTP(S) zip 直链 / 本地 zip

URL 或路径**本身就是版本锚点**；`ref` 字段仅记录（可省）。

### 本地目录（开发中互指）

直接拷贝进 vendor；`ref` 可空。

> 原「不调 Release API」是 git 时代决策（`ls-remote` 免费拿 tag）；无 git 时 API 是唯一可靠来源，已在 §7 记录推翻。

## 4. 命令规格

### 4.1 `tphp new <name> [--lib]`

```
tphp new my-app           # 应用骨架
tphp new --lib foo/bar    # 库包骨架
```

生成：

```
# 应用
mod.json          # name, version 0.1.0, type app, license MIT
main.php          # 入口：require "vendor/autoload.php"; + 起步代码
README.md
.gitignore        # vendor/

# 库包
src/              # 命名空间根目录（示例类）
tests/            # test-smoke.php
README.md
.gitignore        # vendor/
```

`main.php` 示例：

```php
<?php
require "vendor/autoload.php";

echo "Hello, world\n";
```

`name` 校验：应用允许单段名（无斜杠）作为项目名；库包必须 `^[a-z0-9][a-z0-9_-]*/[a-z0-9][a-z0-9_-]*$`（小写，斜杠分层）。

### 4.2 `tphp add <source> [ref]`

source = GitHub 仓库 URL / HTTP(S) zip 直链 / 本地路径（目录或 zip）。

1. 解析 source + ref（GitHub 裸 URL 无 ref → 按 §3 解析最新发布并固化）
2. 查 `mod.json` `deps`：同名已存在则更新 ref 并重装；否则新增
3. 获取内容：HTTP 下载 zip（miniz 解压）/ 本地 zip 解压 / 本地目录拷贝
4. **覆盖前 fail-closed 安全检查**（§7 vendor 覆盖保护）→ 落盘 `vendor/<name>/`
5. 读包内 `mod.json` 取真实 `name`（与 URL 推导不一致时以包内为准，调整路径）
6. 递归处理包的 `deps`（传递依赖拍平；同名冲突：semver 兼容取最高，不兼容 Fatal 并打印依赖链）
7. 写 `mod.json` + `mod.lock`
8. 重新生成 `vendor/autoload.php`

`add` 对已存在依赖 = 更新该包 ref 并重装。

### 4.3 `tphp remove <name>`

1. `mod.json` `deps` 删除该项
2. 递归清理：仅被该包独占的传递依赖删除；仍被其他依赖引用的保留
3. 删 `vendor/<name>/`
4. 写 `mod.lock`，重新生成 autoload.php

### 4.4 `tphp install`

按 `mod.lock` 逐包恢复（vendor 已存在则跳过，离线友好）；无 lock 则从 `mod.json` deps 全量递归解析。完成后重写 lock + autoload。CI/新机器主入口。

**integrity 校验（阶段 E）**：vendor 已存在时不再只看 `mod.json` 在不在——逐文件对照 lock 的 `integrity` 快照；全部匹配才 skip；不匹配（含**新增文件**）→ 报错列出差异文件，`tphp install --force` 显式重装。

### 4.5 `tphp upload`（占位）

不实现远程。输出：

```
发布即推送：
  1. 确保 mod.json 的 version 已更新
  2. git tag v<version> && git push --tags
  3. （可选）未来注册表见 PLAN/pkg-manager.md §7
```

## 5. 架构拆分

新增 C 模块 + CLI 接入；**不动 VM**。

```
src/
├── pkg.c / pkg.h      # 包管理核心
│   ├── mod.json 解析/序列化（轻量专用 + json.c 的 tphp_json_decode_c C API）
│   ├── 获取：HTTP(S) zip 下载（net.c http_get）+ miniz 解压 / 本地目录拷贝
│   ├── GitHub 仓库 URL 改写（gh_repo_to_zip）+ 匿名 API 解析最新发布
│   ├── vendor 布局管理 + 覆盖前 fail-closed 检查
│   ├── mod.lock 读写
│   ├── autoload.php 生成
│   └── 依赖图：递归解析、拍平、冲突检测
│
├── main.c             # CLI 路由：new/add/remove/install/upload
└── (现有) pack.c      # build 自动 --with vendor/（tphp_pack_set_vendor_strict）
```

### 5.1 关键实现点

| 点 | 方案 |
|---|---|
| JSON | 现有 `json.c` 编解码到 TVal；新增 `tphp_json_decode_c`（无 VM、静默）；写回为 pkg.c 手写 pretty printer |
| 内容获取 | `net.c http_get` 下载 zip → miniz 解压；本地目录/zip 直接拷贝/解压；全程无外部进程 |
| GitHub 解析 | `gh_split_url_ref`（`:ref` 切分）→ `gh_latest_ref`（releases/latest → tags semver → 默认分支）→ `zipball/<ref>` |
| semver | 本地比较器：`major.minor.patch`；tags 列表排序用于「最新发布」回退 |
| 传递依赖 | DFS + visited 集；冲突：宽版本约束满足取最高，否则 Fatal 列两条链 |
| autoload 生成 | 遍历 `vendor/*/*/mod.json` autoload 段，拼接 PHP（PSR-4 长前缀优先） |
| 路径分隔符 | 统一 `/`（libuv 同步 fs，Windows UTF-8 路径安全） |

### 5.2 与现有系统衔接

| 系统 | 影响 |
|---|---|
| `require` | **零改动**——`vendor/foo/bar/src/x.php` 字面量路径，现有编译期内联 + 运行期 OP_REQUIRE 均可解析 |
| `tphp build` | 见 §5.3 打包衔接 |
| bundle (phpc) | 不冲突——phpc 是 exe 内置 stdlib，vendor 是项目级依赖 |
| autoload | 生成的 `spl_autoload_register` 走 TinyPHP 已有 autoload 机制 |

### 5.3 打包衔接（`tphp build`）

#### 默认打包集

| 内容 | 来源 |
|---|---|
| 入口脚本 | 命令行指定（如 `main.php`） |
| `vendor/` | 有 `mod.json` 且未显式 `--with` 时自动加入 |
| 用户 `--with` | 显式传入的路径 |

#### `mod.json` 的 `pack` 字段

用户在清单里声明打包偏好，`tphp build` 读取并应用：

```jsonc
"pack": {
  "include": ["assets/", "config/prod.php"],
  "exclude": ["*.log", "docs/", "notes.txt", "vendor/foo/bar/tests"]
}
```

| 键 | 类型 | 语义 |
|---|---|---|
| `include` | string[] | **额外**打包路径（相对项目根；文件或目录）。在默认集与 `--with` 之外追加 |
| `exclude` | string[] | **排除**规则，作用于最终打包集。支持：精确路径、目录前缀（尾 `/`）、glob（`*` `?`，匹配 basename 或相对路径尾段） |

匹配规则：
- 目录规则 `"docs/"` → 整目录跳过（含子文件）
- glob `"*.log"` → 任意层级同名后缀文件跳过
- 精确路径 `"vendor/foo/bar/tests"` → 仅跳该目录
- `exclude` 优先级高于 `include` 与默认集（写了就以排除为准）

示例：

```jsonc
// 应用：打包 vendor + assets，但排除内部文档和日志
{
  "name": "my-app",
  "type": "app",
  "pack": {
    "include": ["assets/"],
    "exclude": ["*.log", "docs/", "assets/internal/"]
  },
  "deps": { "foo/bar": { "git": "…", "ref": "v1.0" } }
}
```

```
tphp build main.php -o demo
# 实际打入：main.php + vendor/**（默认排除 tests/.git）+ assets/**（排除 internal/ 与 *.log）
```

#### 收集排除规则（vendor 自动打包时生效）

pack 目录遍历时跳过以下内容，避免垃圾进单文件：

| 跳过 | 原因 |
|---|---|
| `.git/`、`.gitignore`、`.gitattributes` | VCS 元数据 |
| `.DS_Store`、`Thumbs.db` | 系统垃圾 |
| `*.md` | README 等文档（可选，保持包体精简） |
| 依赖包内的 `tests/`、`test/` 目录 | **测试代码不进生产**；包自身的 `tests/` 同理 |

保留：`mod.json`（运行期可读包元数据）、`src/`、`autoload.php`、其余运行时需要的资源。

> 用户显式 `--with` 某目录时：不跳过 tests/（尊重显式指定），仅跳过 `.git` 等 VCS/系统垃圾。

#### `.php` 文件进 zip（已实现）

`collect_dir` **不再跳过 `.php`**——vendor 里的 PHP 源码是 autoload 运行期 `OP_REQUIRE` 的目标，必须进 zip。VCS/系统垃圾（`.git`/`.DS_Store` 等）仍恒跳过；自动 `--with vendor/` 时额外跳过 `tests/`、`test/`、`*.md`（`tphp_pack_set_vendor_strict`）。

#### 打包前 integrity 校验（阶段 E，待实现）

自动打包 vendor 时先对照 lock 的 `integrity` 快照逐文件校验：不匹配（含新增文件）→ **拒绝打包**（防止把被篡改的依赖打进 exe 分发，与既有 DLL manifest sha1 校验同点位同性质）；无 lock 的手搓项目警告放行。全量 sha1 毫秒级，build 低频不敏感。

#### 端到端链路（打包应用）

```
build 时：
  main.php 字面量 require "vendor/autoload.php" → 编译期内联（磁盘读）
  vendor/** → pack zip（source_root 相对路径作 key）

运行时：
  启动 → pack zip 常驻 → run_source(main) → 编译
  autoload.php 内 require_once __DIR__/... → 字面量折叠后 OP_REQUIRE
    → 磁盘 miss → source_root 剥离 → pack zip 命中
  use Foo\Bar\Str → spl_autoload → require $f（动态路径）
    → OP_REQUIRE → pack zip 命中
```

### 阶段 E — lock integrity 快照（防篡改，后置待实现）

设计定稿 2026-10-21（详见 §2.2 `integrity`）；动机见 [../doc/ffi-security.md](../doc/ffi-security.md)：不走"动态库标识/签名"路线（公开标识可复制、签名需密钥+豁免名单且被系统库调用绕穿），改走"哈希固定 = 我装的是不是我审过的那个"。

- **E1 核心闭环**：`pack.c` SHA1 去 static 导出 → `lock_save` 扫包写 `integrity` → `install` skip 升级为逐文件校验（fail-closed + 新增文件算不匹配）→ `test-pkg-integrity.php`
- **E2 出口把关**：`tphp install --force`；`tphp build` 收集 vendor 前校验 lock，不匹配拒绝打包（对齐既有 DLL manifest sha1 校验点位）
- **E3 可选后置**：zip 源字节哈希（下载先验再解压）、树哈希压缩优化、`tphp verify` 独立命令
- 不做：运行时（`tphp run`）校验、密钥/标识机制、配置开关（与 ffi-security.md 结论一致）

## 7. 边界与已知决策

| 项 | 决策 |
|---|---|
| 远程注册表 | 不做；`upload` 占位。未来若做：`upload` 只传 manifest + tarball；`add <pkg>` 无 URL 时才走注册表，lock 结构不变 |
| 私有仓库 | 不自建 auth 不依赖 git；HTTPS 信任链 = 内嵌 Mozilla CA ∪ 系统 Root 存储（Windows `CertOpenSystemStoreW`）；add 失败透传错误 |
| 包名冲突 | 传递依赖同名：semver 兼容取最高，不兼容 Fatal 报依赖链 |
| vendor 与 git | `tphp new` 默认写 `vendor/` 进 `.gitignore`；`mod.lock` 建议提交（可复现） |
| PHP 版本约束 | 暂不支持 `require.php` 字段（TinyPHP 自身版本即约束） |
| `autoload.classmap` | 暂不做（PSR-4 + files 覆盖主流）；后置 |
| Windows | 无外部工具依赖；路径经 libuv UTF-8 归一 |
| 嵌套 vendor | 禁止（拍平共享，Composer 同款） |
| GitHub 仓库页 URL | `add https://github.com/o/r[.git][/tree/x][:ref] [ref]`：无 ref → GitHub 匿名 API 解析最新发布（releases/latest → tags semver 排序 → 默认分支回退）并**把 ref 固化进 mod.json**；有 ref → `zipball/<ref>`。无 git。原「不调 Release API」决策（§3，git 版时代）已被用户新语义推翻（2026-10-21）：无 git 拿不到 `ls-remote`，API 是唯一可靠来源；限流 60/h/IP 文档已注明 |
| vendor 覆盖保护 | install 覆盖前 fail-closed（对齐 vpm）：目标无 mod.json / 含 .git / 包名不符 → 拒绝 rm -rf，提示手动删除。已实现（2026-10-21） |
| lock integrity | **哈希固定而非动态库标识**（2026-10-21 定稿）：lock 逐文件 sha1 快照，install/build 两校验点，运行时不查；公开标识防不住恶意包（可复制）、签名制被系统库豁免绕穿 → 都不做（阶段 E，见 §2.2/§6） |

## 8. 测试策略

沿用 `tests/` EXPECT 体系；fixture 用本地目录/zip（`pkg_add` 全程无外部工具、可离线），GitHub 形态靠 URL 规则单测 + 实测验证，不打网络。

| 测试 | 内容 |
|---|---|
| `test-pkg-new-app.php` | new 生成文件列表 + mod.json 字段 + 重跑/非法名拒绝 |
| `test-pkg-new-lib.php` | --lib 骨架 + psr-4 自动加载端到端（use + 首次引用触发） |
| `test-pkg-add-remove.php` | 本地源 add → vendor 落盘 + lock + remove + 孤儿清理 |
| `test-pkg-add-deps.php` | 传递依赖拍平 |
| `test-pkg-install.php` | lock 恢复 + 离线跳过（二次 install 不重取） |
| `test-pkg-overwrite-guard.php` | vendor 覆盖 fail-closed 四分支 + 手动删除后可重装 |
| `test-pkg-upload-placeholder.php` | upload 占位输出 |
| （后置）`test-pkg-build-vendor.php` | 自动 --with vendor + 排除 tests/.md + 打包应用可运行 |
| （阶段 E）`test-pkg-integrity.php` | 装 → 改文件 → install 报错列文件；改回 → skip；新增文件 → 报错；`--force` 恢复；无 lock 项目不受影响 |

## 9. 示例：端到端

```bash
# 创建应用
tphp new demo-app
cd demo-app

# 添加依赖（GitHub 仓库 URL，解析最新发布并固化 ref）
tphp add https://github.com/foo/bar

# 指定 tag / 分支
tphp add https://github.com/foo/bar:v1.2.0
tphp add https://github.com/foo/bar master

# HTTP zip 直链（URL 即版本锚点）
tphp add https://example.com/releases/acme-utils-1.2.0.zip

# 本地目录（开发中互指）
tphp add ../acme-utils

# 业务代码写在 main.php（或自建 src/ 后改入口路径）
# main.php:
#   require "vendor/autoload.php";
#   use Foo\Bar\Str;
#   echo Str::upper("hi");

tphp run main.php

# 打进单文件（vendor 进 pack）
tphp build main.php --with vendor/ -o demo
```

```bash
# CI 恢复
tphp install
tphp run main.php
```
