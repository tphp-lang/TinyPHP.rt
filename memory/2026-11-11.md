## 层1 根因定案 + 修复：legacy 八进制字面量缺失（语言级）✅

**PROBE 六态二轮 CI 直出**：`app=y scriptsdir=y rootphp=n modjson=y src=y srcpre=n`——**mkdir 成功、mod.json 写成功（app 根）、两处 `scripts/*.php` 全写失败**（对称+win 同码成功）。**观测坑**：防御让 exit=0 → run.ps1 不触发 DIAG → stderr 探针全被 `2>$null` 吞（首版探针白布）→ 改 stdout 失败路径条件输出（成功轮 probe=0 验证零影响）。

**根因（本地一测定音）**：tphp `echo 0777` → **777（十进制）**，PHP = **511**——lexer 只认 `0x/0b/0o`（lex.c 416），**裸 `0777` 落十进制分支**。链：`mkdir($p, 0777)` mode=777d=**0o1411 → 低9位 0o411 = `r--x--x`**（owner 无 w）→ `uv_fs_open O_CREAT` **EACCES** → root.php/pre.php 不可写；app 根由 C 层 `fs_mkdir_p(0755)` 建（mode 正确）→ mod.json 可写 ✓；**win 绿 = Windows mkdir 忽略 mode** ✓；PROBE 六态全对上。

**PHP 8.5 精确语义（实测）**：`0777`=511/`0755`=493/`0644`=420/`010`=8/`0_77`=63（octal 含 `_` 分隔）；**`08`/`09`/`0778` = 编译期 `Parse error: Invalid numeric literal`**（非执行期、零 stdout）。

**修复（src/lex.c `lex_number`，decimal 分支前插 legacy octal 块）**：`0` + digit|`_` → 八进制扫描（`_` 跳过、遇 8/9 → `lex_error("Invalid numeric literal")` 逐字复刻 PHP 文案、overflow→float 同 0x 分支）；`0` 后非数字（`0`/`0.5`/`0e1`）照原 decimal/float 路。

**验证**：
| 项 | 结果 |
|---|---|
| 双端逐行对拍 | 同测试文件 PHP 8.5 vs tphp **IDENTICAL**（12 案） |
| invalid 案 | `08` 与 `0778` 双端同 255、同文案 "Invalid numeric literal" |
| 新测试 | test-octal-literal-001（12 断言）+ test-octal-invalid-001（EXPECT-EXIT 255） |
| 全量 | **238×1 全绿**（236+2） |
| CI 预期 | `mkdir 0777`→511→755 可写 → root.php 可写 → not found 消失；POSIX-only 语义本地复验不了，**探针保留待 CI 绿后删** |

**顺带记档**：`error_reporting()` tphp 未定义（测试撞见，P1 语言小缺口，不顺手修）；PHP `0778` 双端均已 Parse error。
