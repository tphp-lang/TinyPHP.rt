1. 首轮 perf 无收益 → TPHP_JIT_DEBUG 查明 array-read/kv-read 闭包仍 `eligible(?)=0`。

## 实现（src/jit.c）

1. **eligibility**：`OP_CONST`/`OP_SEND_VAL` 放行 `T_STR`（lit_str 恒 intern → addref/release 皆 no-op，按值存槽安全）；新增 `OP_ARRAY_APPEND` 白名单（base 必须槽位，key/val 槽位或标量/串字面量）。
2. **helper 三件**（镜像解释器语义）：
   - `tphp_jit_array_append`：镜像 do_dim_write append/keyed 两形态（dim_cow + addref val + tarr_set 内部 intern/addref key）。防御 raise 分支实际不可达（literal 构建序列 base 恒为紧邻 ARRAY_INIT 的数组）。
   - `tphp_jit_lit_set`：OP_CONST 字符串走 helper（addref + release 旧 dst + 落值，wtake 语义）；标量仍 store_imm 快路。
   - `tphp_jit_tv_copy`：**OP_COPY/OP_ASSIGN 原为裸 store 无 addref**——放行字符串后 tmp-rc 探针 0xC0000409 实测双重释放（`$b = $a` 复制数组），改为 helper（addref src + release 旧 dst，标量两操作 no-op）。**此为本轮引入放行后的连带必修项**。
3. emit：`OP_ARRAY_APPEND` 走 4 参 helper 调用（key 为 NULL 即 append 形态）。

## P0-10 带键 ASSIGN_DIM（同日完成）

**验收达成**：array-rmw 12.9→**5.7ms（6.79→3.0×，进 5× 带）**；几何均值 ~3.5→**~3.29×**；array-push 57.2ms 无退化；fib 0.94×；224/224 绿。

**实现**：eligibility 放行带键形态（base 必槽位、key/val 槽位或标量/串字面量）；`tphp_jit_assign_dim` 统一 append（key==NULL）/keyed 两形态镜像 do_dim_write 检查序；emit 走 deopt IF 分支；旧 `tphp_jit_assign_append` 删除合并。

**连带修复（崩溃驱动，按序排查）**：
1. **kd 探针 0xC0000005**——gdb 断点抓到真凶不是 longjmp：`tphp_vm_raise(vm, cls, NULL, fmt)` **多传一个 NULL 当 fmt**（签名 `(vm,cls,fmt,...)`）→ `vm_raise_at` → `vsnprintf(fmt=NULL)` 崩。**jit.c 全部 10 处同款调用批量修复**（旧 helper 也一直带着，只是 raise 分支从未被测过）。
2. **append 形态 key=NULL 解引用**（`TVal k = *key`）——重写 helper 时丢 append 分支，gdb `key=0x0` 定位。
3. **deopt 传播链闭环**：helper 本地 setjmp 接 raise → IR `IF(ok==0) RETURN 0` → `call_slots`/`call_dyn` 调用点逐层同款分支 → 最终 `op_do_fcall` C 帧 longjmp（不跨 IR）。`call_dyn` 改 int 返回：callee deopt（exception 已设）禁止 fallback 重跑（防双重副作用）；`call_slots` 入口补 callee entry-NULL 拒编（防读垃圾 ret）。kd3 探针实测 try/catch 正确捕获、Uncaught 行号正确。
4. **热路径 setjmp 性能坑**：setjmp+2×jmp_buf memcpy ≈20ns/call → array-push 1e6 次 append **+24ms（54.9→79.2）**。重构为**快慢路分离**——`tphp_raise_guarded`（错误冷路径才 setjmp，vsnprintf 格式化后以 `"%s",buf` 调 raise），成功路径零 setjmp。array-push 回 57.2ms。**教训：JIT helper 禁止在成功段 setjmp**。

## P0-12 残留跨 IR raise 修复（同日完成）

**验收**：四场景 JIT/解释器输出完全一致——`Undefined array key 9`、`Uninitialized string offset 9`（负索引 `$s[-1]`=c ✓）、`Unsupported operand types in arithmetic`（数组+int）、`$s[0]`=a/`$s[1]`=b（**原版错报 TypeError**）；224/224 绿；perf 同带（array-rmw 3.0× 保持，波动为机器噪声）。

**实现（两类 raise 两种模式）**：
1. **显式 raise（错误分支）→ `raise_guarded` 冷守卫**：`fetch_dim_r` 全部 raise 点——成功路径**零 setjmp**（array-read 1e6 热 fetch 无成本）。顺带**补 string offset 读语义**（镜像解释器 vm.c op_fetch_dim_r 的 T_STR 分支：norm+int key、负索引回绕、越界 UndefinedError、tstr_new 单字符 rc=1 直属 dst）——原版直接 raise 既跨 IR 又错语义。
2. **tval_* 内部 raise（被动、任意点）→ bcall 式事前 setjmp wrapper**：`binop_slow`/`cmp_slow` 改 `binop_slow_body`/`cmp_slow_body` 纯体 + int wrapper（raise 落本地 mine → restore → 返 0）。成本仅慢路径（类型分发 ≥20ns），both-int 快路径不触。
3. **emit deopt 分支**：`call_slow_binop`/`call_slow_cmp` 封装内加 IF(ok==0) RETURN 0 / IF_FALSE 留开——**6 个调用点（lower_binop×2、lower_cmp×2、lower_un NEG/POS、lower_incdec）调用方零改动**；incdec 手写调用重构走封装；fetch_dim_r emit 点同款分支。

**教训沉淀**：raise 守卫两模式——错误分支明确的 helper 用 guarded（零热成本）；被调代码任意点 raise 的必须事前 setjmp（bcall/binop_slow，付在调用频率上——所以 bcall 快慢路结构上做不到，见已知边界更正）。

## P0-13 单态 IC v1 实现（同日落地，未达验收）

**设计定稿**：`DimIC{arr, bk, boff, val_off}` 24B 快照挂 `TOp.ic`——侦察发现该字段对 DIM 类 opcode 本就空闲（仅 CALL 类用），零结构改动。失效验证链 = **arr 指针 + buckets 指针（覆盖 rehash/扩容/L5 惰性重建）+ 桶 key 匹配 + val_off 非 tombstone**，全部锚定当前数组真实状态——关键发现：tarr_unset 的 tombstone **保留 key**（val_off=UINT32_MAX），不比 val_off 会越界读；DimIC 字段非原子竞态写最坏 miss 不会错命中（验证链全用当前 a 的字段），Worker 多线程安全，op->ic 指针写竞态最坏 24B 一次性泄漏。

**改动四处**：value.h（DimIC + 声明）、array.c（tarr_get_ic，key 预 norm 约定；miss 回填快照，absent 置空 ic->arr 防陈旧）、vm.c（op_fetch_dim_r 懒分配接入）、jit.c（helper 加 ic 参数 + emit `ir_CONST_ADDR(op->ic)` 传第 5 参，编译时刻懒分配）。

**实测**（bench-vs-php.php，vs P0-10 基线）：kv-read 58.4→**50.3ms（-14%）**、array-read 15.6→**14.4ms（-8%）**、array-push 57.2→50.6、全表无回退；**224/224 全绿**（28+75+38+19+20+6+8+1+17+12 逐组核对）。
