**三定性**：

1. **主矛 = 属性访问路径（非百菜一撮）**：prop_direct 30-38×、method_get 7.7×（fold mcall 后仍 46ns vs PHP 6ns——call 分发已消，剩 FETCH_PROP helper 本体）、dtor 内 prop 写 tphp +3.43ms vs PHP +0.02ms（PHP 把 dtor 体内写优化没了）。JIT 覆盖实锤：compile(get) size=115（体 = helper 调用壳）+ fold mcall get + OSR 主循环——结构全 JIT，慢在 helper/replay 边界。

2. **次矛 = dtor/free C 侧机械 + alloc**：空 dtor 分发 tphp 1.36ms（PHP 反 2.99ms，tphp 不慢）；dtor 体内 ASSIGN_PROP 走 lower_replay 解释器 pad（jit.c:4310）是 3.43ms 差的主体。alloc+ctor 2.8× 属既有分配器地板（P0-16 已收大部分）。

3. **与刀8/5B 结论不矛盾**：5B 否决的是 helper+setjmp 方案（dtor 直入 +30-40ns/次、ASSIGN helper ≈0）；刀5 记账未做的 **v1.5 = IR 内联 prop IC 快链**（免 helper 边界，per-site class+offset 守卫后裸 load/store）从未实施——本轮主矛指向的正是它。



**PHP 为何 0.18ms**：tracing JIT 对热对象 prop 做 store-to-load 转发/内联 offset（1.8ns/iter）；tphp 每次 tphp_jit_fetch_prop 造假帧跑真 handler（~70ns）。量级差 = C helper 边界，非算法。



**下一刀候选（主）＝ prop IC 内联快路（刀5 记账 v1.5）**：

- 形态：FETCH_PROP/ASSIGN_PROP 热站点 → per-site 快照（class 身份 + prop offset + 无 magic）→ IR 裸 load/store TVal，守卫失败落既有 helper/replay（语义零漂移）；

- 攻击面：prop_direct 30-38×、method_get 7.7×、dtor 内写 3.43ms——object 2.6× 预期降到 ~1.5-1.8×；

- 风险：magic __get/__set 守卫、继承 prop 布局、引用语义（&\->v）、COW 对象；镜像 DimIC 纪律（守卫失败完整兜底）；

- 不做：dtor 直入（5B 已证伪）、ASSIGN_PROP helper（≈0）。

## prop v1.5 批1：FETCH_PROP IR 内联快路（TPHP_PROP_INLINE，默认开）——object −14% ✅

**选靶**：object 侦察批主矛（memory 前节）——prop_direct 38× / method_get 7.7×，根因 = tphp_jit_fetch_prop C helper 边界（假帧+setjmp+真 handler ~70ns vs PHP 内联 offset ~1.8ns）。

**实现（src/jit.c 单文件）**：
- 布局锁：TProp/TObj/TClass/GCHead offsetof _Static_assert 八条（PLAN/prop-ic.md §2.4）。
- 开关 prop_inline_enabled()（TPHP_PROP_INLINE=0 关，同二进制 A/B）；仅 t2==OPD_CONST && lits[].t==T_STR && prop_helper 开生效，动态名/开关关 → HEAD 路径零改动。

- 踩坑：ir_SHL_U64(slot,…) 的 slot 是 I64 → type 11≠5 ir_check=0；改 ir_MUL_I64(slot, TVAL_SZ) 修复。
