# 2026-10-21 HTTPS 证书问题诊断与修复

## 症状
`tphp add https://github.com/tphp-lang/lib_rt` →
`PHP Warning: https: handshake with github.com failed: X509 - Certificate verification failed`。
但 example.com / curl.se 的 HTTPS 都正常。

## 诊断路径
1. net.c 握手失败路径只有 mbedtls_strerror 的笼统文案 → 先补诊断：
   `MBEDTLS_ERR_X509_CERT_VERIFY_FAILED` 时调 `mbedtls_ssl_get_verify_result` +
   `mbedtls_x509_crt_verify_info` 打印标志位（net.c tls_connect）。
2. 重建后标志位 = `0x8` = `MBEDTLS_X509_BADCERT_NOT_TRUSTED`（链不受信；
   非过期、非域名不符）。
3. `openssl s_client -connect github.com:443` 看真实链：
   - subject=CN=github.com
   - issuer=CN=SteamTools Certificate, O=BeyondDimension, C=CN ← **假证书**
   - 机器上装有加速器类工具（SteamTools/Watt Toolkit 家族）对 github.com
     做 TLS 中间人；其 CA 在 CurrentUser\Root 存储（2026-12-21 到期的那张有效）。
   - 浏览器/Go/Node 用系统信任库所以正常；tphp 内嵌 Mozilla 包不含该私有 CA
     → 拒绝握手是正确行为。

## 修复（用户拍板：并入 Windows 系统信任库）
- net.c `tls_cacert_load_win_store()`：`CertOpenSystemStoreW(L"ROOT")` 枚举，
  逐张 `mbedtls_x509_crt_parse_der` 追加进同一条信任链；单张失败忽略。
- 非 Windows `#ifdef _WIN32` 跳过；Linux CI 不受影响（build.sh 无改动）。
- build.cmd 两处 link 行加 `-lcrypt32`。
- 信任面 = 内嵌 Mozilla ∪ 系统 Root（union，与 Node 常见构建一致）。
- 验证：github.com/example.com/curl.se 全通；178 passed 0 failed；零警告。

## 顺带确认的设计边界（非 bug）
- `tphp add` 只吃 **zip 直链 / 本地路径**（PLAN/pkg-manager.md + doc/
  package-manager.md 明文：无 git 依赖、不做 GitHub API、URL 即版本锚点）。
- 传仓库页面 URL（https://github.com/foo/bar）会下载到 HTML →
  "invalid zip archive"，符合设计。
- lib_rt 默认分支是 **master** 不是 main：正确用法
  `tphp add https://github.com/tphp-lang/lib_rt/archive/refs/heads/master.zip`
  （实测通过：vendor/tphp/lib_rt + mod.json deps 落盘）。

## 排查工具箱
- `openssl s_client -connect host:443 -servername host -showcerts`（PS 里用
  cmd /c 包一层，PowerShell 不支持 `</null` 重定向）。
- net.c 握手失败的 verify flags 输出是永久诊断，别删。
