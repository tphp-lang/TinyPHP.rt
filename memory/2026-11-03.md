**崩溃与根因（deps/ir emit 三 pass 乱序，cf39e5d 的反例）**：
- **症状**：JIT=1 第二次 t1() 崩 "Attempt to assign property v on object"；DX2 实锤 opseq 收到 `fn==slots==ctor TFunc*`（指针值躺 slots 位）。
- **链路**：ctor 体单 ASSIGN_PROP pad → `tphp_jit_opseq` 六参 {vm(rcx), fn CONST→rdx, slots PARAM2 读点→r8, pc CONST→r9, ...}；post-RA dump（TEMP-RADUMP: `d_3 {R2} {%rdx}=PARAM slots` + CALL 实参读点 `%rdx` + `c_7=fn 常量`）证明**装载目标 rdx = 拷贝源 rdx**。
- **根因**：cf39e5d 把 `ir_emit_arguments` 改为"MEM/CONST 装载先于 REG→REG 洗牌"，其安全性论证（"LSRA 为每个 arg hint reg 在 call load pos 建固定窗"）在 **CONST 实参上是半开区间空话**——窗口与 operand 读点同一 `IR_LOAD_LIVE_POS` tick，slots 钉 rdx home 与常量窗口不被判冲突；emit 先 `movabs fn→rdx` 再 `mov rdx,r8` → 实参错位。**两场景同形状方向相反**：MEM 装载=恢复 RA 寄存器段（cf39e5d concat 必须装载先行）、CONST 装载=引入新值（拷贝必须先搬走 pre-load 内容）——emit 无法自辨，只能让 CONST dst 显式让路。
- **为何只有 ctor 崩**：普通函数 slots 跨 call 活跃/被 spill，读点不在 rdx；ctor 体单 pad、slots 区间 [entry..call] 短 → 钉 rdx home 必撞 fn 常量位。
- **修复 pass 1.5（四文件同调：ir_x86.dasc / ir_emit_x86.h / ir_aarch64.dasc / ir_emit_aarch64.h）**：pass1 记 CONST→REG 目标（`const_dsts[ncd]`），洗牌前先发射"**源=常量装载目标**"的拷贝子集（CONST dst 恒不为拷贝目标——每实参位单一 mover → 子集独立、可先行）；MEM 装载保持洗牌前（cf39e5d 不回退）；pass2 注释勘误。**大坑重申：只改 .dasc 无效，build 编的是预生成 ir_emit_*.h，必须手工同款补丁同步**。
