## array-read 守卫/LICM 勘察（P0-17③ 第一步：可行性定案）

**背景**：性能优先拍板（用户）；vs-PHP 缺口地图（linux-x86 tphp/PHP）：array-read **5.94×** 全表杠杆第一（ln 值 1.34/14），logstat 4.08 / alloc 3.83 / object 3.67 / kv 3.22 / rmw 2.33 / fib 1.91；14 项 13 输 1 赢（throw 0.78×）——几何均值 ≈2.04（**tphp 平均慢 2 倍**；勘误：11-03 曾把方向读反说"已达标"，实为未达标）。

**勘察实锤**：
1. **deps/ir 无 LICM**：IR_OPT 全集 = INLINE/FOLDING/CFG/MEM2SSA/CODEGEN/TAILCALL（ir.h:662-667），O1 管道无任何 loop-invariant code motion → 通用 LICM = 新写 pass（大 + speculation 安全论证复杂），**不推荐先做**。
2. **编译路径 = fn 级**（array-read 闭包 eager n_ops≤96，bench 首调编译；无对应 osr 行）→ **投机外提不可用**（fn 级无 resume-pc，守卫失效只能 RETURN0 重启 = 双执行）；**但"循环体内无修改点"静态证明下的纯 LICM = 零投机零 deopt 语义，完全可行**。
3. **循环结构**（最小复现 tmp_ar.php + DEBUG=2 dump）：内层 i 循环 IR 00232..01959 ≈ **1725 静态节点**（多 BB：END/MERGE/IF_FALSE 控制节点密集）；ULT bounds 守卫在 00331。热路径组成（实读两段）：
   - 循环条件段 ≈25 条：4 LOAD（$i/$n tag+pay）+ 2 EQ(=INT) + AND + GT + IF + 双 STORE 分支
   - packed 守卫段 ≈30 条：base tag EQ → IF → packed U8 LOAD + key tag EQ → AND → IF → n LOAD+ZEXT → ULT → IF
   - fold_add 快线 ≈40 条（tag/payload + 溢出 nof + fast 直写）
   - **未解块**：体内另有大段内联（GE/LE tag 值域 + GC kind U8/AND + ADD/SUB I32 回写 + 2 个 CALL + deopt RETURN 门）——疑为 `+=` 完整语义/INC 慢线/快照 store 被展开，**动态热路径实际执行多少条未量化** → 收益占比未知。
4. **可外提候选（安全证明最简单的子集）**：base slot 的 tag/payload LOAD、packed U8 LOAD、data/n LOAD + 对应 2-3 层 IF——前提 = 循环体内（header..backedge）对 base 槽零 store + 无 CALL/pad（静态可扫）；**key tag（$i 由 INC 写，溢出可变 FLOAT）与 acc tag（慢线可改）不能外提**，留残余。

**下一步（待拍板）**：POC 先行——**emit 层手动 preguard**（路线甲）：预扫描回边建循环体 pc 表 → 循环 header 先发 invariant 守卫（T_ARR/packed/data/n）→ 体内 FETCH 只留残余（key tag/ULT）+ 慢路 v1 helper 完整兜底（语义零漂移）→ tmp_ar + bench array-read A/B 量化；若收益 <预期再评估路线乙（deps/ir LICM）或扩外提面。emit 层循环分析工程估 200-400 行（可复用 OSR 的 header/backedge 收集逻辑 jit_cfg_ok/osr_collect_exits 思路，函数级首次引入回边预扫描）。

## teb 首跑第二波（11-04）：enum case 关键字语法 bug 已修 ✅ + autoload 深层 arity bug 挂账 ⏳

**Bug A（已修）**：`enum Features: int { case Default = 0; }` → Parse error "Expected enum case name"。
- 根因：`Default`/`List` 是半保留字（lex `ident_kind` 大小写不敏感 → KW_DEFAULT/KW_LIST），parse 的 **enum case 定义位硬判 `kind != L_IDENT`**（parse.c:2341），而 `->`/`::`/方法名位早已用 `tok_is_member_name`（L_IDENT || KW_IF..KW_FROM——注释明说"关键字在成员位置退化为标识符"）放行；lex 对关键字 token 无条件填 `tok.ident`（lex.c:589）。
- 修复：case 定义位改走 `tok_is_member_name`（parse.c 一处）。回归：test-keyword-members.php 追加 `case Default = 0; case List = 7;` + `::Default->value`/`::List->value` 用例；**243/243**。

**Bug B（已修 ✅，同日）**：teb `new Web()` → `ArgumentCountError: Too few arguments to function {closure}(), 0 passed ... exactly 1 expected`。
- **根因**：`compile_thunk` 存的 fn_idx 相对**宿主类自己的 Program**（每文件 tphp_compile 独立表，funcs[0]=占位），`tphp_call_thunk` 却查 **`vm->prog->funcs[idx]`（主表）**——动态 require（autoload）的类在主表错位：Web ctor thunk idx=1 → 主表 funcs[1]=autoload 闭包（n_params=1、RECV line9=autoload.php:9，全部实锤吻合）。单文件/同 prog 场景（thunk 与主表同表）不炸 = 隔离矩阵全通的原因。
- **定位法**：[ARG] raise_arg_count 帧探针（fn/file/opline/**caller op=RECV pc=0**）+ [AL] autoload 时序探针（只有 Web/Base 两条 =炸帧不经 autoload 调用）→ 收敛到 thunk 帧（sent=0/n_caps=0/prev=__construct=RECV 求值上下文）。
- **修复**：`tphp_call_thunk` 改用**调用帧宿主的 `fn->prog`** 查表（RECV/常量 thunk 的调用帧恒为宿主 fn；无帧回落 vm->prog）——vm.c 一处。
- **回归**：`tests/lib/test-thunk-reqprog-001.php` + `helpers/thunk_reqcls.php`（动态 require 独立 Program + ctor enum-case 默认值 thunk，同时覆盖 Bug A 的 Default 半保留字）PASS；**243→244 全绿**（注：跑法 tphp test tests\lib =29 passed）。
- **teb 侧连带（teb 仓库已改）**：`Web.php` options 键 `timeout_ms` → **`request_timeout_ms`**——civetweb 对 unknown option 直接 mg_start 失败（二分实测：timeout_ms 任意值 FAIL、request_timeout_ms ok、num_threads/auth ok）。
- **端到端**：`tphp run teb/tests/hello.php` → HELLO **200 `hello from Tphp\Teb`** + ROOT 200（首页 HTML）、route 闭包/Request::method(GET) 全通。探针 [ARG]/[AL] 全撤。
