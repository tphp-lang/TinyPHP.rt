## 刀9：动态调用兜底路径 JIT 分发补齐（`tphp_vm_call_callable` 非 recv 直调 + call_user_func 族守卫 pad）——`TPHP_DYN_JIT=0` 关，默认开

**缺口复现（刀5C 诊断的落地）**：`tphp_vm_call_callable` 非 recv 路径（闭包/普通函数）在 hot 门编译出 `jit_entry` 后，帧仍走 `run_frame_until_pop_deep` **纯解释器**——JIT'd caller（bench 计时壳）动态调用的被测闭包首调整段解释执行、长循环中途 OSR（`=1` 全表 DEBUG 实证：每个被测闭包多 1 条 `osr compile`，array-push 虚高 2.2×/rmw 5.8×/string 2.9×）；usort 族/call_user_func/FFI 回调/Closure::call/trampoline 兜底同走此缺口——**被动态调用的 callee 即使已编译也永不以 JIT 执行**（10-30 P0-15① 只补了 hot 门没补分发）。

**实现**（src/vm.c + ext/builtin/builtin.c）：
- 非 recv 路径帧构建后（`vm->x.frame = f` 之后、水位复位之前）插 op_do_fcall ~1687 同款直调：`!fn->is_method && fn->jit_entry && n >= n_params` + 实参洞（UNDEF）守卫 → 槽 `poff = clo ? n_cap : 0` 拷参 addref → `e(vm, f->slots, &jret)`。三支路镜像 op_do_fcall：成功 = 消费队列引用（release+清 UNDEF）+ 弹 rec + frame_destroy + 恢复 prev 帧（NULL 置 done）；异常 = 释放队列引用后 `TPHP_LONGJMP` 上传（JIT'd 帧无内部 try/catch——emit 白名单拒绝——无 JIT'd 帧内 resume 面；槽副本/捕获由 frame_destroy 收）；deopt（返 0 无 exception）= 落下方解释器，RECV 先 release 槽副本再 move 队列引用（op_do_fcall:1744 同协议）。is_method 跳过（静态方法经字符串可调用的 poff 布局歧义且不在受益面）；variadic 靠准入天然排除。
- **与 op_do_fcall 的有意差异**：e() 期间**不复位 args 水位**（保持 base+nq）。op_do_fcall 先复位（~1628）再直调 → callee 内 opseq replay 的 SEND 按 `n_args++` 写队列、踩掉本调用的原始 arg 引用（clean deopt 后 RECV 读到 UNDEF 走默认值/arity 误报的暴露面，**op_do_fcall 侧既有、另案记录 backlog**）；保水位则 replay 排队恒在本调队列上方，成功/deopt 分支内再复位。
- **call_user_func / call_user_func_array 补守卫 pad**（顺带修既有挂死）：此前直调 call_callable 无 pad——callee 内部 try/catch 捕获自身 raise 时 longjmp 穿过 builtin C 帧 → 主分发器在 callee 帧内部分恢复（catch 跑完帧弹出）→ builtin C 帧废弃、调用点 dst 永不写 → 主循环踩未写值**挂死**（JIT=0 纯解释器同样挂，`call_user_func("fn")` + fn 内 try 即触发，PHP 正常）。改走 `tphp_vm_call_guarded`：正常完成（含内部 catch）返 1；逃逸返 0 且 exception 已设 → `TPHP_LONGJMP(vm->x.unwind, 1)` 重抛（与既有 builtin raise 同路径）。usort/array_map 族同类无 pad（比较器/回调内部 catch 同挂死）——**另案记录**，本刀只修 call_user_func 族（探针覆盖面）。

- **审计探针**：tools/audit_array_builtins.php（24 函数双端对照，长期保留——新 builtin 加进来跑一遍即可）。

**环境坑新增**：wsl.exe 在助手沙箱黑名单（Linux 侧验证需用户手动）；EXPECT 行禁非 ASCII（GBK mojibake 破坏匹配）；python 打 /tmp 需 cygpath -w。
