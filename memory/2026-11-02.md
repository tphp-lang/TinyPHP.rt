
## 11-02 续：call-域定量分解（P0-9 立项数据）——方法分派无罪，通用调用机制是主因

**探针**（tools/probe_call_ovh.php，1e6 × 2 轮，Windows 本机）：

| 段 | PHP 解释器 | tphp 解释器（JIT=0） | tphp JIT 直调 |
|---|---:|---:|---:|
| free-call（静态函数，无参空体） | 38-40ns | **107.6ns** | 8.9ns |
| pure-call（$o0->noop() 方法） | 39.4ns | 104.6ns | — |
| new-only（new C0 无 ctor） | 52.4ns | 99.3ns | — |
| new+noop | 83-87ns | 141-150ns | — |

**关键结论**：
1. **方法分派无罪**：pure-call 104.6 ≈ free-call 107.6（MCALL 快照后分派 ~0）——~67ns/调用差额全在**通用调用机制**（frame_alloc+memset / slots UNDEF 填充 / rec 推拉 / 帧切换循环力学 / JIT hot-gate 分支）。
2. **JIT 直调 8.9ns = 机制上限证明**：同一调用 JIT 化后 12× 于解释器（free-call 循环纯计算型被 OSR/JIT 化；方法调用循环含对象 op 被 OSR 拒编——批 2-3 撤回域）。
3. **与 PHP 的 2.7× 差距 = 解释器调用架构差**：PHP 每调用 38-40ns（specialized handler + arena 帧 + computed-goto），tphp 104-107ns。
4. **两条修复路线**：①解释器帧瘦身（增量：memset→字段化 / UNDEF 填充合并 / hot-gate 分支精简——需先插桩定位 67ns 构成，rdtsc 已证伪改用减法实验）②**对象 op 进 JIT**（INIT_MCALL/NEW 过 OSR——被批 2-3 的 deps/ir O1+FOLDING CSE bug 阻塞，与 kv hash 直选同上游）。
5. **战略推论**：现有两条主线（kv hash 直选、OSR 对象 op）都卡在 deps/ir 上游——**向 dstogov 报最小复现**成为杠杆项（一份材料服务两条线）。

**立项状态**：P0-9 call-域 = 数据齐（本节），设计未展开（需先插桩定位 67ns 构成）。探针入库 tools/probe_call_ovh.php。

## 11-02 续4：P0-9 call 域插桩归因——67ns 构成定案，帧瘦身证伪，下一刀 = OSR 方法折叠直调

**方法**：减法实验（组件开关构建对照）+ `--dump-opcodes` 精确 op 计数 + 探针增强（新增 empty-loop / nop-call 两段锚点）。用户拍板"继续"后执行。

**双侧分解表（JIT=0，1e6 次，ms≈ns；PHP 8.6-dev 本机）**：

| 段 | PHP | tphp JIT=0 | gap | tphp JIT=1（全 OSR） |
|---|---:|---:|---:|---:|
| empty-loop（7 op 分派基线） | 11.6-12.4 | 59.8-62.2 | **+49** | 6.6-6.7 |
| free-call（10+2 op） | 38.4-39.5 | 106.6-107.1 | **+67** | **8.9-9.0（4.4× 反超）** |
| nop-call | 36.0-37.3 | 101.7-105.0 | +65 | 8.9-9.2 |
| pure-call（方法，9+1 op） | 39.1-39.6 | 106-107 | +67 | **64.8-65.3** |
| new-only | 49.4-50.1 | 97.3-97.4 | +47 | 60.7-61 |
| new+noop | 84.5-88.6 | 141.4-142.6 | +54 | 121-122 |

**归因（67ns = ①49 + ②19）**：
1. **①+49ns（73%）= 通用每 op 执行率**：空循环即差 5×（61 vs 12）。op 计数口径 ~8.7ns/op vs ~1.7。结构根源两刀：**(a) 每 op 一次间接函数调用**（vm.c run 循环 `((OpHandler)cop->handler)(vm, cop)`——handler 指针 call/ret、prologue、无法跨 op 内联；非 computed-goto `goto *table[]`）；**(b) TVal TMP 物化**（`LT→t13; BOOL_VAL t13→t14; JMPZ t14` 三段式 = 每轮条件 4 次 16B 槽往返；PHP 栈上一步）。→ 结构修复 = **P2-16 L4 computed-goto**（量化依据齐，目标 ~2-3ns/op）。
2. **②+19ns（27%）= 调用机械超额**（46 vs 27）：SEND/RECV 参数 ≈4ns（free−nop 差）；**双 memset ≈0**（V1：删 op_do_fcall 第二次 memset，107.1→107.6 噪声内；8 个建帧点都重复 memset frame_alloc 已清零的帧）；**UNDEF 填充承重**（V2 跳过 → 0xC0000005，frame_destroy 按 tag 释放靠它——不可去）；余 = INIT/DO/RETURN handler 本体。→ **原路线①"解释器帧瘦身"收益 ≤2ns，正式证伪不立项**。
3. **默认配置（JIT=1）现状**：探针 6 段循环全进 OSR（header 8/42/76/112/147/179 全编译），free-call 折叠直调 9ns 已反超 PHP 4.4×；**剩余缺口 = 方法/new 走单 op/序 opseq replay 经 C helper**（pure-call 65 = empty 6.7 + replay 58 vs PHP 方法机械 27）——批2-3 只放行了白名单，未做批2-2 式折叠直调。
4. **下一刀（高 ROI，建议下轮）**：**OSR 内 INIT_MCALL/INIT_NEW 折叠直调**（扩批2-2 折叠 CALL 机械）——预期 pure-call 65→~15-20、new+noop 122→~60、new-only 61→~30。结构线 P2-16 computed-goto 为解释器全线 ~3× 的长期杠杆（防翻案记录已在案，现补量化依据）。

**过程记录**：V2 崩溃实测证明填充承重（回滚）；`--dump-opcodes` 是现成字节码反汇编口（此前未用过——新发现的工具）；双 memset 8 处同型（frame_alloc 自清零 + 各调用点再清）实测零收益不动码。探针增强（empty/nop 段）保留为归因锚点。

## 11-02 续5：OSR 批2-4 INIT_MCALL 折叠直调落地——pure-call 5.2×、对 PHP 3.2× 反超

**执行 P0-9 归因指出的下一刀**（用户"继续"）。设计要点（全档 PLAN/osr.md 批2-4 节）：
- **fold 条件（INIT_MCALL emit 时）**：`j->osr`（**函数级不折叠**——避开 deopt 重启语义）+ `op->ic` 已固化单态 user 方法 + `(mfn==j->fn || jit_entry)` + **`jit_body_frameless`**（新扫描：callee 体含 prop4/ISSET_DIM/FE/INIT_NEW/NEW_USER/INIT_MCALL 任一 replay op 则拒——**直调链不推 VMFrame，真 handler 会读 vm->x.frame 落进调用方帧**，这是本批最关键的正确性防线）→ 否则原 p_seq=2 序回放兜底。
