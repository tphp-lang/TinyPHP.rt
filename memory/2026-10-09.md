## M0 骨架完成（TinyPHP.rt 运行时项目，C:\project\tphp\TinyPHP.rt）

- **mimalloc 断言根因修复**：`options.c:449 mi_add_stderr_output: mi_out_default == NULL` 断言失败。
  根因：clang 目标 `x86_64-w64-windows-gnu` 定义了 `__MINGW32__`，但 mimalloc 源码不自动定义
  `MI_MINGW_UCRT64`（官方 CMakeLists.txt:679-682 检测 MSYSTEM=UCRT64 才加）。缺该宏时
  `prim.c:794` 条件为 false → `MI_PRIM_HAS_PROCESS_ATTACH` 未定义 → prim.c:40 的 constructor
  编译进产物；同时 windows/prim.c:905 的 TLS 回调（.CRT$XLB）也在。loader 阶段 TLS 回调先跑
  `_mi_auto_process_init()`，随后 .ctors constructor 再跑一遍 → 进程初始化执行两次 → 断言。
  **修复：build.cmd 的 mimalloc 编译行加 `-DMI_MINGW_UCRT64=1`（连同 `-DMI_STATIC_LIB`）**。
  Linux/macOS 不需要此宏。
- **僵尸进程坑**：断言崩溃（0xC0000409）的 tphp.exe 进程不会自然退出，残留 8 个，锁住
  build\tphp.exe 导致重链接 `Permission denied`。重构建前先 `Stop-Process` 清理。
- **M0 验收通过**（Windows 实机）：
  - `build\tphp.exe -v` → `tphp 0.1.0 (x86_64-w64-windows-gnu, libuv 1.53.1-dev)`
  - `--uv-version` → `libuv 1.53.1-dev (api version 79105)`，`-h` 帮助正常，均 exit 0

  Linux 链 -lpthread -ldl -lrt -lm）、`clean.sh`。
