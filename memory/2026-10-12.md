## 【质量】ASAN×FFI 0xC0000005 修复

### 现象
ASAN 全扫 84→87 前：3 个 FFI 调用类测试（m5.5-acceptance / simple-calls / wchar）0xC0000005；cdef/new/sizeof/字段读写不崩；普通构建全绿。

### 根因（非 fiber 注解缺失）
**`ffi_prep_cif` 不拷贝 arg_types 数组**——parse_function 里 `ffi_type *atypes[32]` 是栈数组，cif.arg_types 指向它；cdef 返回后悬垂。普通构建靠栈未复用侥幸存活；ASAN use-after-return/栈复用即读到 0xffffffffffffffff → ffi_call_int+92 movq (%rax)。

lldb 定位：`movq (%r12,%r14,8),%rax` 加载 arg_types[0] 为坏指针；r12=cif+8。

### 修复
- **ffi.c**：atypes 改 tm_malloc 堆分配，FFIFunc 加 cif_atypes 字段与 cif 同寿命（scope 永不释放）
- **fiber.c**：同时按 php-src zend_fibers.c 协议补全 ASAN fiber 注解（save 留在 switch/suspend 局部、jump 返回后自己 finish；首达 finish(NULL)；垂死 start(NULL)；finish 输出刷新对侧 asan_bot/asan_sz）。真根因是 UAF，但注解是 M4-a 教训 5 预留的正确补全，防止后续 fiber 栈 ASAN 盲区

### php-src 协议（zend_fibers.c:511-541）
- start(&fake_stack, to->stack->asan_*) 在 jump 前；save 是局部变量
- jump 返回后 finish(fake_stack, &to->stack->asan_*) —— 同一侧 resume 时消费
- trampoline 首达：finish(NULL, &from->stack->asan_*)
- DEAD：start(NULL, ...) 不保存垂死 fake stack
- asan_pointer/asan_size 初始化 = 分配边界，finish 输出刷新

- 普通：87/87
- ASAN：82/82 test-*.php + m5.5-acceptance + m6-acceptance 全过

## 打包器跨平台（Linux ELF section + macOS footer）

### 用户要求
"Linux和macos section都要实现" —— 打包器不再仅 Windows PE。

### 实现（src/pack.c 重写 + pack.h 去掉 _WIN32 门禁）
- **共享**：SHA1、--with 收集（POSIX opendir 版）、miniz zip、逐条目释放（sha1+原子 rename）、zip-slip 防护、__main.php 嵌入主脚本
- **Windows**：PE RCDATA TPHP_BUNDLE + TPHP_MAIN（zip 不含 __main.php，脚本独立资源）
- **Linux**：ELF section `.tphp_bundle`（objcopy --add-section；无 objbin 回落 footer）
  - 运行期解析 ELF64 section header + shstrtab 查找
- **macOS**：文件尾 footer `[zip][u64 le size][magic "TPHPBND1"]`
- Unix 自身路径：/proc/self/exe、_NSGetExecutablePath
- tphp build 跨平台（Unix 复制自身 + chmod 0755）

### 修复
- main.c `#ifdef _WIN32` 未关导致整个 main 包进 Windows 分支 → 拆开
- build_zip 签名 char** vs uint8_t** 不匹配
- MoveFileA → MoveFileExA(REPLACE_EXISTING)
- self[] 未初始化
