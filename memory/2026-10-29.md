## 本轮：P0-13 v2 实现（用户"下一步吧" → 按推荐续作）

**实现**（src/jit.c + value.h + vm.c）：
1. **双快路全内联**：每个 FETCH_DIM_R emit 生成 packed int 直取 + DimIC hash 链 7 层两条互斥快路。链序照抄 `tarr_get_ic`（arr→buckets→bpending→bp→val_off→key tag→key pay）——**buckets(ic->bk) 比较先于 bp 解引用 = 跨线程撕裂写序（arr 先写）下垃圾 bp 的安全门**，v1 的"链全锚 live 状态最坏 miss"论证照搬。packed 边界用 `(u64)key < (u64)n` 单条无符号比较（负数=巨大无符号天然覆盖）。
2. 命中 leaf = `tphp_jit_dim_take`（addref+release+store 语义单点，C call）；miss/非数组/raise 全落 v1 helper + deopt（5参 call + IF RETURN 0）——**语义与 v1 单 call 完全一致，仅热路径消 call 框架**。
3. 结构 = 递归逐层 IF + END + MERGE_2（lower_binop 既有姿势，顶层 MERGE_2 后留活线继续 emit_seq）；`JIT_CTX()` 局部需 `JitC *j`——三个辅助函数补 `JitC *j = g->j`。
4. **generic 回退门（JSC 同款）**：`DimIC.misses`——IR 链失败 ++、仅 IR 叶子命中清零、**helper 回填不清**（防轮转键 site 反复解锁）、≥8 跳链直 call helper 永久锁死；锁死态/非数组/packed 越界不计数。

**排障两坑（教训）**：
1. **`ir_ZEXT_U32` 产出类型仍 U32**（宏后缀=目标类型不是"扩到更大"）→ 塞 `ir_SHL_U64` 触发 ir_check 类型不兼容（4!=5）——且 **ir_check=0 不 gate 照常出坏码**（size=5360 照跑）。修复用通用 `ir_ZEXT(IR_U64, x)`。**铁律：每轮 JIT 改动后必须盯 `[jit] ir_check=1`**（224 绿不足以发现——测试跑过了坏码，只是没崩）。
2. **首版无门 kv 反涨 27%**（50.3→63.6ms）：bench kv 是 8-key 轮转（`$m[$keys[$k]]`），单态 IC **恒 miss**，每次白付 7 层失败链（+13ms ≈ 1.6e6×8ns 吻合）。**单态 IC 对轮转键站点天生无效**——诊断探针形态教训：`TPHP_JIT_DEBUG` 确认闭包 eligible=1 后，先看 ir_check 再看数字。

## P0-13 v3 + v3.1：多态 N-case 链 + take 全内联（同日续作）

**v3 多态链**（value.h / array.c / jit.c）：
- `DimIC` 重构：共享 `arr/bk`（数组级）+ `cases[8]{b}` FIFO 装填 + 内嵌 `dead` 哨兵（val_off=UINT32_MAX 恒拦）。
- **关键设计推演（防返工）**：case 的"空槽"与"key 不配"是**两个失败入口**，若各递归下一 case 会**指数膨胀**——哨兵使空槽 b 恒非 NULL → 每 case 归一**单 bool**（tag+pay && 非tomb）→ T=叶子/F=下一 case 线性递归。
- **写序铁律**：cases（重置为哨兵）**先于**共享 arr/bk 写——读侧共享层是安全门（看到新共享 ⇒ cases 已安全）；指针单指令原子写。
- C 侧 `tarr_get_ic` 多 case 化（数组/桶表变化 → 先清 cases 再刷共享 + FIFO）；`tphp_dim_ic_init` 统一初始化（emit/解释器两处懒分配共用）。
- 实测 kv **56.6→51.4（-9%，8 槽全覆盖轮转键）**。

**v3.1 take 全内联**：
- 镜像 `tval_addref`+`tval_release` 热路径——**顺序严格：先 addref v 后 release dst**（v 与 dst 可能同对象，先增后减防归零——C 同序）。
- 快路判定推演：ref 区间 `[T_STR,T_CLOSURE]` 连续；INTERNED=flags 字节 LSB（GC_FLAG_INTERNED=1）；**release 的 rc>1 快路与 color DEAD 正交等价**（DEAD rc>1 也是 rc--）→ 免查 color；标量/interned/rc==1 → **call `tval_release` 原样**（rc==1 的 call 覆盖 DEAD rc-- 与 switch destroy 两分支，与 C 逐分支等价）。
- 每个 IF 一 diamond（5 个连环 MERGE_2）——LOOP 内 diamond 已有 lower_binop 先例 ✓。
- 实测 array-read **11.5→9.9（-14%）**；C 版 `tphp_jit_dim_take` 零引用删除。

**当日合计（v1→v3.1）**：array-read 15.6→**9.9ms**（-26%总体、2.68×）、kv 50.3→52.7（打平但架构升级为全内联多态）、几何均值 3.19→**~3.06×**、224/224、每轮 **ir_check=1**（铁律执行到位）。

## P0-14 批3 前置（10-29 续）：INIT_NEW 对象链规格（用户拍板批2）

**目标**：object bench（tools/bench-vs-php.php object 1e5：循环内 `new class(...)` + `$o->get()` + `unset`）闭包进 JIT。审计 INIT_NEW×1 只是对象簇首拒因——白名单当前零对象 opcode。

**opcode 面（闭包本体）**：INIT_NEW / SEND_VAL / NEW_USER（匿名类编译期注册，同 named）/ INIT_MCALL / SEND / DO_FCALL(mcall) / UNSET_CV。ctor/get/dtor 体是独立函数，无需准入（由回放的 op_do_fcall 帧切换同步解释执行）。FETCH/ASSIGN_PROP = 闭包本体不碰 → 归批3-2（函数据 prop 读写时）。**排除**：NEW_EX/LATE/DYN、SEND_SPREAD、JMP_NULL、FCC_METHOD、嵌套调用（emit fail → 编译回退解释器，语义安全）。

**核心架构 = 回放真实 opcode 序（零语义重复）**：`tphp_jit_opseq(vm, pc_start, pc_end, recv_sc)` 放 **vm.c**（需 vm_unwind_core/静态件；jit.c 顶部 extern 声明）：
- bounded-pad 守卫（tphp_vm_call_bounded 同构：save outer unwind → setjmp(vm->x.unwind) → floor=jf=JIT 帧 → 落地 vm_unwind_core(jf,&escaped) → escaped→restore+return0（exception 必已设 ✓ 符合"guards precede writes"deopt 铁律，vm.c:1701-1707）；catch→重注册继续跑）；
- 回放循环驱动 `jf->pc`（volatile vpc 长 jmp 安全；每 op 前 jf->pc=vpc 保归因）：INIT_NEW/DO_FCALL/NEW_USER → 直接跑真 handler（call_push/op_new_user 读 lits[稳定]、dst 写回 frame 槽=JIT 槽 ✓）；SEND_VAL/VAR → 真 handler 从槽读（与既有 arg_copy-at-DO 同时点同值，225 测试背书的活性）；其余 op（CONST/表达式）→ **跳过**（JIT 已求值）；帧切换（op_do_fcall/new_user 返0 且 jf->pc 已自推）→ 深跑 `while(frame!=jf)` 至回帧；
- **INIT_MCALL 特例**：op_init_mcall 读 recv 槽（INIT 位置活性，回放在 DO 时点读可能已被实参表达式复用）→ INIT_MCALL-emit 点把 recv 快照进 `j->r_call_clo` scratch（entry ALLOCA 循环内安全）；helper 以快照值调 vm.c 拆分出的 `init_mcall_core(vm,op,objv,mname)`（= op_init_mcall 2609-2700 原文抽函数，零重复）；**方法名 ar 必须 CONST**（动态名 → emit fail 回退）。

## 差距诊断：vs Zend tracing JIT（用户问"没写好还是没写到"，对照 php-src 8.5.7 实测）

**结论：主要是"没写到"（三个代差），不是"没写好"。** 已做的 IC/内联/direct-slot/回放方向都对（fib 0.93 反超证明 ir 后端+直调路线正确）；差距来自 Zend 是 DFG 级架构而 tphp 是白名单 baseline。

**代差（php-src 实测证据）**：
1. **opcode 覆盖面**：ext/opcache/jit/zend_jit_ir.c = 17994 行 / 1558 处 zend_jit_* lowering，几乎全 opcode × 类型形态组合直发机器码；tphp jit.c 白名单制 + replay 兜底（object/call/prop/foreach 大量形态落 C 路径或 per-op 回放）。
2. **类型推断（SSA/DFA）**：Zend trace 内类型传播后 tag 不再 load/check（裸 GPR）；tphp 每 op 仍 load_tag/load_pay——**TVal tag 每次过内存** = 31ns vs 6.3ns 的核心。注意：纯 MEM2SSA 已试=反效果（10-27），正解=先局部类型传播再消 tag。
3. **call 全特化**：Zend call IC + 直呼 callee + 寄存器传参；tphp call = ir_CALL C helper（41.6ns vs ~2.6ns，16×）——**最大单点差距 + 几何均值主杠杆**。

**工程债（真"没写好"）**：①单 op replay 每次付 bounded setjmp ~20ns（ISSET_DIM 零 raise 白付）→ 零 raise op 免 pad 直呼；②多态 case 顺序扫描（轮转键全扫）→ MTF。

**路线**：call 特化（直入 jit_entry+参数寄存器化）> 批3-2 ctor/prop > 类型驻留 > setjmp 免除 + case MTF。整体 3× 才到 M2（≥1.0），单靠修债不够，必须补覆盖面。

## P0-15 call 特化第一批（用户"开始"）：静态直调 + call_dyn 帧合并

**A 静态直调**（jit.c lower_static call）：call_slots C 调用替换为 **jit_entry 运行期 load + 间接 ir_CALL**（消 runtime lookup C 帧）；INT 契约改 IR 逐参 IF 检查（失败 RETURN 0，与 call_slots 返 0 语义同构=callee 未执行→caller deopt，免 diamond 合流）。**坑**：①ir_OR 需显式类型且比较结果类型合并踩 ir_check 不兼容（1!=10）——改嵌套 IF 短路；②ir_EQ/ir_NE 是二参宏。self 递归仍走 call_slots（entry 编译期 NULL，fib 不受益）。
