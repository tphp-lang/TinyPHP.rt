## pebview 异步 bind（C:\project\tphp\pebview）

- 需求：JS 侧 `await window.fn()`，PHP 处理函数要在线程里跑，不能卡 UI。
- 三条硬约束定死拓扑：①webview_bind 回调在 UI 线程的事件循环里同步执行 ②webview_return 只能 UI 线程调（WebView2 STA）③tphp FFI 回调 trampoline per-thread，C 跨线程调 PHP 闭包 = UB。→ **必须加 C 桥**：`pebview_return_async(handle, id, status, result)`（native/pebview_async.c，内部 strdup + `webview_dispatch` + UI 线程 `webview_return`）。handle 传 `CData::getAddress()` 的 int（CData 不能跨线程序列化）。
- 实现：`include/Pebview.h` 加声明（tphp 符号惰性解析，缺符号只在调用时报错，不破坏旧路径）；`src/AsyncBinder.php`（线程池 + 轮转派发 + dispatch 内 try/catch，因回调内 throw = 硬 Fatal）；`src/Window.php` 加 `bindAsync($name, $handler, $threads=2)`；`src/worker-entry.php` 工厂；`tests/async-demo.{php,html}`。
- **tphp 限制**：Worker 入口闭包必须编译进**主 Program**（`worker_serialize_closure` 用 `vm->prog` 查索引；autoload 的库文件属 inc_progs 且刻意不 freeze）→ 工厂函数放 worker-entry.php，主脚本必须**字面量** require。闭包也不能跨 Worker 序列化（NotCloneableError），所以处理函数只能是顶层命名函数。
- **本次新发现的 tphp bug**（已在 README 记录，未修）：
  1. 返回类型写全限定名 `function f(): \Foo` → Parse error（PHP 合法）
  2. 方法内 `call_user_func("f", 1, C::m(), "x")` → 假的 ArgumentCountError（"3 passed ... exactly 3 expected"），先落局部变量可绕过
  3. 属性类型 `?ClassName` 被转小写后比较 → "Cannot assign X to property of type ?x"
  4. webview 的 `webview_return` status=0 才是 resolve（原 bind 传 1，promise 恒 reject）
- 另修：Base.php 去 BOM；`setSzie` 保留 + 新增 `setSize`；destroy 幂等（原 destroy+__destruct 会二次 webview_destroy）。
- **兼容性红线（用户明确要求）**：不得为了新功能改动既有行为。`bind()` 已**逐字还原**（json_decode ?? [] / 原样回传 $result / status=1），`Base::getFFI()` 逻辑与 `$isArm` 判断原样保留（只抽了 libPath/headerText 供 Worker 复用）。三个既有问题（status=1 恒 reject、$isArm 恒真、BOM）只在 README 记录，等用户拍板再改。
- 状态：链路已实测跑通（bound → dispatched → Worker 执行 → 调 pebview_return_async 报 symbol not found → stopped）；`hello.php` 原用法实测仍可用（legacy-ok / destroy-ok）；**只差重编 DLL**（库源码不在本包）。

## 异步 API 重构（单一 `Tphp\` 命名空间，194 passed）

### 修掉的四个 bug

1. **`is_callable` 不认 `__invoke` 对象**：`tphp_vm_call_callable` 根本没有 T_OBJ 分支（`$obj()` 走 opcode 分派，两条路各管各的）。抽 `tphp_vm_is_callable()` 统一判定，补 T_OBJ 分支；`op_init_dyn` 只认 `m->fn` 不认 native `__invoke`，一并补上。顺带 `type_name` 的 `T_OBJ → "object"`（原 "unknown"）。
2. **关键字成员名**：`$o->fn` / `$o->match` / `function fn()` 全报 Parse error。`parse.c` 加 `tok_is_member_name()`（`L_IDENT` 或 `KW_IF..KW_INSTEADOF` 区间），`->`/`?->`、方法声明、trait `::` 四处改用它。
3. **组 use**：`use function Tphp\{async, await};` 不支持。新增 `parse_use_prefix()`（遇 `\{` 停在前缀），`KW_USE` 分支重写为"前缀 + 组循环"。
4. **协程内 uncaught 异常 SIGSEGV（P0）**：`build_root_frame` 创建根帧时漏设 `f->file` / `f->vis_scope` / `f->called_cls`，`tm_malloc` 不初始化 → `raise_file()` 读到 mimalloc 已释放填充值 `0xd0d0...` → 打印 `in %s` 时崩。连带修好闭包跨 spawn 访问 private/protected（曾报 "Cannot access private property"）和 `static::class`。

### 新增能力

- **Channel 多等待者 FIFO**：`TChan` 的 `recv_waiter/send_waiter` 单槽改成 `head/tail` 队列 + `TCont.chan_next/chan_val`；send 优先交接队首 recv，close 唤醒全部。可直接当信号量做并发限流（预置 N 令牌，`finally` 归还）。
- **`Coroutine::wait()`**：await 的对象式别名。
- **`Tphp\TaskGroup` / `Tphp\Thread`**：`spawn`/`wait`/`count`，wait 按登记序返回结果数组（幂等）。
- **`async(EXPR)` 语法结构**：parser 改写为 `Tphp\spawn(fn() => EXPR)`——调用表达式整体搬进协程，自由变量按 spawn 时点按值捕获（复用箭头函数的自动捕获）。`$obj->spawn(EXPR)` 同规则。非调用形态（`async($callable)`）退化为包装成 `Tphp\Task`，函数名统一改写为完全限定名，免 use。
- **单一命名空间**：删掉 `Async\*` 7 个函数、全局 `async`、全局 `Thread`；类名 `Async\Coroutine|Channel|TaskGroup|Task` → `Tphp\*`。

### 坑与约束

- 类名 `tstr_intern` 带长度参数，改名必须同步改长度（15→14 / 13→12 / 10→9），否则截断。
- `async` / `spawn` 成了**准保留名**：parser 按名字匹配，用户自定义同名函数/方法（单实参是调用表达式时）会被改写覆盖。
- `AsyncCancelled` 保留（全局异常类，不在 `Async\` 下，catch 与测试都在用）。
- 增量构建用 `scripts/incbuild.sh <files...>`：全量 `build.cmd` 会重编 libuv/mbedtls/mimalloc 几百个文件，改一行 C 要等几分钟。

### Worker 命名空间统一（同日追加）

- `tphp\Worker` → `Tphp\Worker`，`tphp\WorkerContext` → `Tphp\Worker\Context`。
- 顺带修文档错误：`Tphp\Worker\Worker::self()` **从未存在**——`self()` 是 `Tphp\Worker` 的静态方法，子线程里返回 `Tphp\Worker\Context`。
