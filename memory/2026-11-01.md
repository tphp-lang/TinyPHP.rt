## 追记 2：NO_MIMALLOC（CRT）mac-arm 读数——判别树分叉，两簇税源分离实锤

| bench | CRT (mac-arm) | mimalloc (mac-arm) | 常规 (arm64-linux) | 判定 |
|---|---:|---:|---:|---|
| serialize | **60.5** | 148.7 | 139.6 | CRT 快 2.5× |
| json | **150.8** | 295.1 | 336.1 | CRT 快 2.0× |
| array-push | **10.1** | 32.7 | 26.5 | CRT 快 3.2× |
| string | **0.6** | 0.9 | 0.9 | CRT 快 1.5× |
| real-logstat | **72.2** | 92.5 | 64.1 | CRT 快 20%（混合） |
| **alloc-probe** | **85.2** | 91.3 | 29.1 | **不动，仍 2.9× 于 linux** |
| **object** | **156.7** | 159.1 | 29.1 | **不动（opool 不过分配器）** |

**分叉结论**：
- **簇 1（serialize/json/push/string）= mimalloc Darwin 行为税 ✓ 实锤**（CRT 快 1.5-3.2×）。修法先走**零代码判别**：`MIMALLOC_PURGE_DELAY=0 MIMALLOC_PAGE_RESET=0 ./build/tphp run tools/bench-vs-php.php`——serialize/json 恢复接近 CRT = purge/page-reset 策略税，env 或 mimalloc 编译选项固化即可，无需换分配器。
- **簇 2（alloc-probe/object）= 与分配器无关**（CRT 换掉纹丝不动；opool 本就旁路）。剩余嫌疑：①macOS libmalloc 自身慢（CRT 构建 alloc-probe 85.2ms vs linux glibc 29.1 = 2.9×——**macOS system malloc 的 malloc/free 对基线成本**）②tphp 自有 TLS（gc_list/cls_tab/tphp_vm_current——CRT 构建同样存在）。**下一判据 = mac 上跑 tools/bench_alloc.c（纯 C，无任何 tphp TLS）**：malloc/free 对 ~400ns+ = macOS libmalloc 基线慢（→ 换分配基座或池化绕开）；~50ns = tphp TLS 层实锤（→ TLS 整合路线）。
- **kv 6.79× 归因同步修正**（见上条追记）：真实差距，PHP zend_hash 小数组快路 vs tphp norm+探测链——tarr_get 小数组（n≤8）线性扫描直取是下一个立项候选。

**判别树现状**：bins ✗ → TLS 总量 ✗ → mimalloc Darwin ✗（簇 1）/ ✓（簇 2 非分配器）→ **bench_alloc.c 纯 C 基线 = 唯一分叉点**。

## 追记 4：MIMALLOC_SHOW_STATS 读数——purge 假设复活（10-31 前提被证伪）

**stats 关键行**（bench 全套，elapsed 0.978s）：
- `purged: 19.0 MiB / purges: 53`——**purge 实际发生了 53 次**！10-31 "purge_delay=1000ms、100ms bench 不应触发"的前提**被证伪**：①bench 全套 elapsed 0.978s 跨过 1000ms 阈值；②abandoned 页收割路径独立于 delay（abandoned 5.4K）。
- **purge 的真实代价 = 后续再触页软错误**：MADV_FREE_REUSABLE 后每页再写 ~2-5µs × 19MiB≈4864 页 ≈ **10-25ms 级**，且与 bench 项切换的分配模式变化耦合——**正是 serialize/json/logstat 轮间方差的候选机制**（上轮 CRT json 150.8 vs 本轮 248.6 的不一致也可能与 purge 状态相关）。
- `extended: 49.2K`——页扩展 4.9 万次 = 分配模式伸缩抖动（每 bench 项大数组分配→释放→下一项重扩），元数据成本候选。
- `arenas: 1 / mmaps: 3 / os allocated: 0`——单 arena 常态，无 os abandon 异常。
- `malloc req 401MiB / peak rss 376MiB`——bench 全套正常量级（logstat 样本 + serialize seen 表）。

**判别 A 升级为"有直接证据支撑"**：`MIMALLOC_PURGE_DELAY=0 MIMALLOC_PAGE_RESET=0 ./build/tphp run tools/bench-vs-php.php`——ser/json/logstat 若恢复接近 CRT 水平 = purge/page-reset 税实锤，env 固化（或 mimalloc mi_option 固化进 main.c 启动）即修簇 1。
**判别 B（bench_alloc.c 纯 C 基线）仍待跑**——簇 2（alloc-probe 82-91 / object 144-163 四构建稳定）的唯一分叉点。

## 追记 5：同命令第二份 stats——runner 方差 ±18% 实锤，判别协议修正

同命令（MIMALLOC_SHOW_STATS=1）两轮对比：**bin 表/purge 计数逐字节一致**（purges 53 / purged 19.0MiB / extended 49.2K 恒定 = 分配行为确定性 ✓），但 **elapsed 0.978→0.798s（-18%）**。
- **判读：mac runner 单轮运行间方差 ±20%**——上轮"json CRT 150.8 vs 248.6 未复现"的大头可能就是 runner 噪声而非 purge 状态差异；
- **协议修正：mac 上的判别读数必须多轮取 min**（沿用项目既有 5×5 交替 min 纪律），单轮对比在本平台不可信；
- 判别 A（MIMALLOC_PURGE_DELAY=0 MIMALLOC_PAGE_RESET=0）仍有效但要求 ≥3 轮取 min 对比默认态 ≥3 轮取 min；判别 B（bench_alloc.c）输出通常稳定，单轮即可。

## 追记 6：三轮曲线 = 暖机曲线（非随机方差），协议再精化

elapsed 三轮：**0.978 → 0.798 → 0.741s**（-24% 后收敛），分配 stats 三轮逐字节一致（purges 53 恒定）。
- **判读修正**：不是随机 ±18% 方差，是**首轮冷启动税**（页 fault/缓存冷/分支预测器冷）——第二轮起趋于稳定（0.798 vs 0.741 差 7% 收敛中）。
- **协议精化**：mac 判别读数 = **丢弃首轮，第 2 轮起取 min**（比 5×5 更省）；判别 A/B 对比基准也要用"丢首轮后"的默认态（0.798/0.741 这档）。
- purge 53 次恒定 × 三轮 = purge 行为完全确定性 ✓——判别 A 的逻辑链（PURGE_DELAY=0 消掉 53 次 purge 的再触页成本）依然成立。
