## ext 管线跨平台分栏：os.<平台>.sources + .m 收集（tui 三窗口后端驱动）

- **动机**：tui 包（CUI 1.4.0 封装）要同时打 Windows/macOS/Linux，三平台窗口后端（win32/x11/cocoa）编译单元不同——cocoa 是 Objective-C（`.m`），原管线只收 `*.c` 且所有平台编同一套源。
- **管线改动（ext/pkg/pkg.c）**：①源收集改收 `.c` + `.m`；②`TExtSpec` 新增 `os.<平台>.sources`（与 cflags/libs/ldflags 同款分栏，append 语义），编译时 = 公共 sources + 当前平台 sources，**非当前平台目录不扫描、缺失不报错**；解析/释放/writer 三处同步（mod.json 写回不丢字段）。
- **契约同步**：PLAN/ext-packages.md（§2.1 sources 行、§2.2 合并语义、§5 流程第2步、§10 决策#4 追加注记）、doc/ext-dev.md §4 manifest 契约。
- **测试**：tests/pkg/test-pkg-ext.php 夹具三平台 os.sources **双向锁定**——正向：init 依赖的 `tphp_ext_tst_extcmd_extra` 符号只存在于「当前平台」源目录（不扫=链接失败 add-FAIL）；反向：各平台文件带 foreign `#error`（误编外平台=编译失败）。CI 五平台（Win/Ubuntu×2/macOS×2）自动回归。
- **实证**：重链后 tui 包产物 58 个 .o 只含 `cui_backends_win32_*`，无 x11/cocoa；主套件 249 passed 0 failed。
- **tui 包三平台结构**：`cui/backends/{win32,x11,cocoa}` 移出公共 sources 递归域，公共源 = `src` + `cui/src`；macOS `os.darwin.cflags: ["-fobjc-arc"]`（实测 clang 对 .c 输入也接受）、`ldflags` 三 framework；Linux `-lX11`（需 libx11-dev）。本机无 Linux 环境（WSL 仅无 bash 的 docker-desktop、Docker daemon 未启动）——Linux/macOS 包编译未本机实跑，契约由 CI 五平台 test-pkg-ext 覆盖。

## tui 全功能覆盖：spec → 310 方法全量实施（.trae/specs/expand-tui-full-coverage）

- **规格**（用户 /spec 批准）：覆盖规则 = cui.h 全部组件级入口减排除清单（帧循环/字体度量/主题只读/ID 内部件/glfw-sdl 后端）；分10任务、助手层先行、6 域并行。
- **实施（6 域文件 + 助手层）**：tui_util（参数/数组助手：tui_strs/floats/ints/bools 两趟执行 raise 不泄漏、tui_arg/opt 全家）→ tui_widgets（显示小件38法）→ tui_form（表单35法，buffer 往返 + 值型返回新值 + 日期族）→ tui_layout（容器导航90+法，含 table/dataGrid/treeTable/filterBar/停靠/看板；跨 begin/end 借阅用静态暂存）→ tui_charts（图表21法，series/items 等结构体数组两趟转换）→ tui_content（富内容70+法：markdown/codeEditor/hex/terminal/log/commandPalette/tour/gantt/file/图片/emoji/社交/签名/节点编辑 + devtools 族 testExplorer/stackTrace/requestBar/uptime/timeHistogram/coverage/blame/featureFlags/apiExplorer）→ tui_app（savePng/fileDialog/openUrl/主题查询/测试面）。**注册方法总数310**。
- **测试面（Task 7）**：simulateMouse/Key/Text + lastRect/getRect；交互冒烟13断言含「注入点击使 button 返回 true、toggle 翻转、PNG 截图魔数校验」。
- **交互时序实测结论（记档 coverage.md）**：frame() 阻塞等事件（simulate* 注入即事件可泵帧，纯 move 可能不唤醒）；每段布局只含本段组件、rect 在 present 时写入 state、last_id 每段清零→**读 lastRect 前必须先调组件**（取上一段布局）；输入按上一段 rect 命中；点击时序 = hover 落段 → down → 下一段 up 与组件调用同段返回 true；**同窗第二段注入阶梯会因残留输入状态失效**（button/toggle 分两 App 实例）。
- **过程中揪出两个真 bug**：①`toggle` 双重翻转——`cui_switch_ex` 原地翻转 `*value`，封装层又翻一次抵消（原始切片就有，交互测试首次暴露）；②**随机 AV（16-20% 复现）**：文件标记逐步收窄 + gdb 定位 SIGSEGV 于 `cui_accordion_begin`（cui_data.c:48 读垃圾 `cui__current` 索引）——根因 = cui.h `CUI__SCOPE_IF` 类 **14 对 begin/end**（popover/menu/contextMenu/dialog/sheet/accordion/table/tree/hoverCard/expandableCard/userMenu/dockPanel/dataGrid/nodeEditor）begin 返回 false 时 CUI 未开节点，封装层无条件调 End 关掉了父节点 → node 栈失衡。修复 = 每类型静态标记守卫 End（PHP 侧仍可无条件调），**压测45轮0崩溃**（修复前必挂）；连带教训：stdout 管道缓冲会吃掉崩溃前输出，定位要用 file_put_contents 落盘标记。
- **交付物**：tui/src 7 文件、tests 7 冒烟 + run.ps1 一键驱动（PASS=7 FAIL=0）、example 5 例（hello/todo/form/dashboard/markdown，WM_CLOSE 关窗 exit=0 实测）、README 全量分组 API 表、doc/coverage.md（覆盖矩阵/排除清单/opts/借阅/SCOPE_IF/测试面时序/三平台依赖）。tui 不在 git 仓（未初始化）。
